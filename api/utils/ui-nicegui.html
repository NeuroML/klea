UI — NiceGUI¶

The NiceGUI web frontend is composed per app (klea_agent.ui.web / klea_rag.ui.web, ADR-0031): each app builds its page from the shared components below. klea_utils provides only the reusable helpers and components, never a full page.

Shared frontend helpers¶

These are framework-agnostic: the NiceGUI web frontend and the TUI share one source of truth for chat/session state, the API client, the stream-event reducer, and transcript export.

In-memory chat state shared by the Klea frontends.

Framework-agnostic session-state store for the web (NiceGUI) and terminal (Textual) clients: the per-chat ChatData cache and the helpers that operate on it (create-or-get, sorting, choice resolution, credential checks). Keyed by {user_id}:{chat_id} so colliding chat_ids across different users do not interfere.

Framework-agnostic stream-event reducer shared by the Klea frontends.

The /query/stream SSE events are turned into frontend state by apply_stream_event(), a pure function: it mutates the chat dict it is given and returns an action string, touching no UI, no HTTP and no NiceGUI. The web (NiceGUI) and terminal (Textual) clients consume the same reducer, so the event-to-state contract lives in one place; the UI-driving coroutines (run_stream / stop_stream) stay in each frontend.

See devdocs/system/streams.md and devdocs/system/tui.md.

Frontend identity resolution (ADR-0050 invariant I5).

Frontends (the Textual TUI and the NiceGUI web UI) resolve their user_id through one seam: an explicit --user-id / KLEA_USER_ID, then a persisted (machine-local) UUID. The persisted UUID is only sent to a loopback server, so it is never leaked to a remote deployment; a remote server without an explicit identity gets an empty user_id (the server treats user_id as an opaque token).

Framework-agnostic model-configuration helpers (shared by web and TUI).

The model-config dialog exists twice (a NiceGUI dialog and a Textual modal) but the logic behind it does not: parsing a role’s model string into editable fields and joining them back, deciding the credential scope and status of a (possibly unsaved) model, collecting the roles that changed, and persisting a role’s override. This module holds that logic with no frontend imports, so both frontends share one source of truth. The frontends keep only their own widgets and styling (a tone is mapped to a colour class per frontend).

Text helpers¶

Human-readable formatting for streamed inspection details.

NodeStreamData.details is structured JSON (dict/list/scalar) carried over the inspect stream event. json.dumps escapes embedded newlines, so multi-line values such as prompts collapse into a single unreadable line. format_details() keeps the JSON shape but renders string values faithfully: embedded newlines become real line breaks, and a value that is itself a JSON object/array is inlined and pretty-printed. The output is plain text, for any frontend (the NiceGUI inspector, the TUI).

The structure, indentation and quote/backslash escaping are all delegated to json.dumps. Only the two value transformations are custom (see _prepare()), because json.dumps always escapes newlines.

klea_utils.ui.inspect_format.format_details(details: Any) → str[source]¶

Render structured inspect details as readable indented JSON.

The structure matches json.dumps(..., indent=2); only string values are treated differently:

  • embedded newlines are kept as real line breaks (at their original column, so the text is not altered), so multi-line prompts read as text;

  • a value that is itself a JSON object/array string is parsed and inlined as nested, pretty-printed JSON;
