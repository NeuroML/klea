Commands¶

Shared session-command framework (ADR-0047): the command catalogue, parser, registry, and the graph-side handler contract. See Session commands for the user-facing catalogue.

Common¶

Common components of the session-command framework.

Commands are the user-driven analogue of tool calls (ADR-0047): the user chooses the command instead of the model choosing a tool. This module holds the shared mechanics – the Command metadata, a CommandRegistry, the /command parser (with a // escape), the CommandContext handed to handlers, the CommandResult they return, and /help rendering – with no frontend or app imports. Each frontend routes an input that starts with / by the command’s klass; app-specific handlers are registered with the app. See devdocs/system/session-commands.md.

class klea_utils.commands.common.Subcommand(name: str, summary: str, arg_hint: str = '')[source]¶

Bases: object

A first-class verb of a command (ADR-0047).

A command with subcommands is a small verb tree: the first argument selects the verb (see resolve_subcommand()), and the remaining arguments are the verb’s own. The command’s single handler branches on ParsedCommand.verb.

Parameters:

  • name – Canonical verb name (lower-case, without the leading slash).

  • summary – One-line description (shown by /help).

  • arg_hint – A short usage hint for the verb’s arguments.

klea_utils.commands.common.parse_command(text: str) → ParsedCommand | None[source]¶

Parse text as a /command, or return None.

Only a leading / as the literal first character counts (no leading whitespace). A leading // is an escaped literal slash and is not a command (use unescape_command() to recover the literal text). A command with no name, or with malformed quoting, is returned with ParsedCommand.error set rather than raising.

Parameters:

text – The user input.

Returns:

A ParsedCommand, or None when text is not a command.

klea_utils.commands.common.render_help(registry: CommandRegistry, capabilities: Iterable[str], name: str = '') → CommandResult[source]¶

Render /help output for a frontend with capabilities.

With name, show that command’s detail; otherwise list the available commands (filtered by capability). The output is Markdown: the command usages in inline code and, for a command detail, bold Aliases / Subcommands labels. A chat frontend then renders one command per line with a monospaced usage (plain newlines would collapse into a single paragraph).

Parameters:

  • registry – The command registry.

  • capabilities – The frontend’s capabilities.

  • name – An optional command name to describe.

Returns:

A CommandResult with the rendered lines.

klea_utils.commands.common.resolve_subcommand(command: Command, parsed: ParsedCommand) → ParsedCommand | str[source]¶

Resolve a command’s verb from parsed, or return an error message.

Commands without subcommands are returned unchanged. For a command with subcommands the first argument selects the verb:

  • an empty argument list resolves to the bare form (verb == "", the command’s default behaviour, e.g. a listing);

  • a known verb name returns a copy with verb set and args/raw_args reduced to the verb’s own arguments;

  • an unknown verb yields an error string naming the valid verbs.

Parameters:

  • command – The resolved command.

  • parsed – The parsed input.

Returns:

The updated ParsedCommand, or an error string.

klea_utils.commands.common.unescape_command(text: str) → str | None[source]¶

Return the literal input for an escaped command, or None.

A user types //foo to send the literal text /foo (a message, not a command); this strips one slash. The // must be the literal first characters (no leading whitespace). Returns None when text is not an escaped command.

Parameters:

text – The user input.

Returns:

The unescaped text (/foo), or None.

Graph¶

Graph-side support for the session-command framework (ADR-0047).

Holds the graph-command handler contract and its result type, plus the entry router that decides whether a query is a server-side command. The CommandNode itself lives in klea_utils.nodes.command.

See devdocs/system/session-commands.md; ADR-0047.

Bases: object

The outcome of a server-side command handler.

Parameters:

  • details – Inspect-event details.

klea_utils.commands.graph.command_query_router(state: BaseModel) → str[source]¶

Return "command" for a command query, else "continue".

The router makes a single decision: is the query syntactically a command (a leading /, with // escaping a literal slash) or a general query? The command node does the rest – validating the name, dispatching an executable command, or replying with a direct message for an unknown, client-side, or not-yet-implemented command.

Parameters:

state – The graph state (its query is inspected).

Returns:

"command" or "continue".

klea_utils.commands.graph.command_route_router(state: BaseModel) → str[source]¶

Return a command’s handoff route, or "" for a terminal command.

The command node writes the handler’s GraphCommandResult.route to the transient command_route state field; the app’s conditional edge maps this label to a graph node ("" -> END). Used as the path function of add_conditional_edges immediately after the command node, so a workflow command can hand off to another node (e.g. /compact -> the summarise node) before the run ends. See devdocs/system/graph-routing.md.

Parameters:

state – The graph state (its command_route is read).

Returns:

The route label ("" when the command is terminal).
