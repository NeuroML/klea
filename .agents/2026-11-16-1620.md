# Session: 2026-11-16-1620

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash

## Objective
Make the structured plan status (content blocks) mark the same steps as current
as the plaintext plan during a tool-dispatch round, so a parallel fan-out round
no longer looks idle, and record the change in the docs and changelog.

## Completed
- Diagnosed why the two plan surfaces diverged: the plaintext `display` rendered
  by the shared tools caller passes `current_numbers` (the distinct step numbers
  stamped on the batch's calls), while `plan_content_blocks` derived its current
  step from the single-runnable frontier (`plan.current_step()`). During a
  parallel round the frontier is one step, so every other dispatched step fell
  back to `pending` in the structured items.
- Extended `plan_content_blocks` with an optional `current_numbers` set and
  threaded it through `_step_role`; `None` keeps the previous single-frontier
  behaviour, so the Planner and Evaluator emitters are unchanged.
- Had `AgentToolsCaller` forward the batch's dispatched step numbers (same
  collection the base hook gives to `plan.render`) into the structured blocks,
  so all three `key="plan"` emitters agree.
- Documented the parameter in `devdocs/system/streams.md` and
  `devdocs/system/agent-node-contracts.md` (section 5.11) and added an
  Unreleased "Fixed" changelog entry.

## Errors and Lessons
- The divergence was not a rendering bug but a source-of-truth mismatch: the
  structured emitter needs the same explicit current-step set the plaintext
  render is given, rather than re-deriving the frontier itself. Keeping the
  argument optional preserved the single-step callers without touching them.
