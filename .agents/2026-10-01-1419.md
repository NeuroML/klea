# Session: 2026-10-01-1419

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Fix the tool picker so it binds tool arguments under strict structured
output (it emitted `args: {}`), then refactor the shared LLM node base so
per-run execution state lives in a per-run `NodeContext` instead of
`_last_*` instance variables.

## Completed

- Root-caused the empty-arguments bug: the picker asked for a free-form
  `args: dict[str, Any]`, which Anthropic and OpenAI strict structured
  output both close to `{}`.  Verified live with Opus and Haiku.
- Fixed it by building a per-run, strict-safe discriminated-union schema
  from the disclosed tool set (each tool's parameters as typed fields, a
  `no_tool` branch, `{step, reason, call}` wrapper).  Scope is the same
  disclosed set as the prompt descriptions so prompt caching is preserved;
  per-step tool restriction stays prompt-only.  Documented in ADR-0044.
- Added `model_type` (inference kind) to `LLMModel`, separated it from
  `model_role`, gave the tool picker a dedicated `tool_picker` role (no
  silent fallback), and added a "use for all roles" action to the shared
  model dialog.
- Fixed a HuggingFace token regression: provider-field filtering stripped
  `huggingfacehub_api_token`.
- Completed the `NodeContext` refactor in five review-gated chunks:
  0. additive scaffold (`NodeContext`, `LLMNodeContext[TOutput]`,
     `ToolCallerContext`), populated alongside `_last_*`;
  1. exec/streaming hooks;
  2. LLM invoke/process hooks;
  3. prompt-phase hooks;
  4. `_validate_result` / `_update_state`;
  5. deleted all shared per-run node state (`_last_*`,
     `_validation_feedback`, `_token_usage`, `_final_state`, per-run
     `_output_schema`); `_update_output_window` now receives the prompt
     explicitly.
- Documented the refactor in ADR-0045; removed the resolved backlog item;
  updated `streams.md` and ADRs 0019/0044; updated `CHANGELOG.md`.
- Fixed the last remaining per-run instance state: `SummariseMemoryNode`
  kept `self.conversation` / `self._window_start` across runs; the window is
  now recomputed from `state` by `_summarisation_window`.
- Added an architecture guard (`utils_pkg/tests/test_node_state_hygiene.py`):
  node classes may assign `self.<attr>` only in `__init__` or a
  `@property` setter, enforced by AST parsing of the three `nodes/`
  packages; documented in ADR-0045.
- Removed `Planner.set_tools_info`: `tools_info` is now a constructor
  argument (it is built before `_create_graph`, like `ToolsPicker`), so
  the guard needs no `set_*` exception.
- After E2E showed Haiku (as `tool_picker`) running a bare `pytest` instead
  of the named file, hardened argument binding: added "narrowest call" /
  "reuse exact identifiers from observations" rules to the agent
  `ToolsPicker_system.md`, a scope note to the `run_command` field
  description, and synced the RAG picker prompts to the strict-safe
  argument contract.
- Fixed a Python 3.12 regression from the NodeContext refactor: the
  `TCtx: NodeContext = NodeContext` default is PEP 696 (3.13+); removed it
  and passed the ctx type explicitly at the use sites.
- Added the deferred live-tool-status / `run_command`-output UX items to
  `devdocs/backlog.md`.

## Errors and Lessons

- The picker bug was a contract mismatch, not a weak model.  A 30-line
  live check (or reading the provider schema transform) would have shown
  strict mode closes free-form objects before any prompt tuning.
- `cached_property` (`output_schema_json`) plus a per-run schema is a
  latent stale-cache bug; computing the schema prompt from the passed
  schema removes it.
- A large mechanical signature change is safest as one atomic chunk per
  hook group, with `state` kept as a separate explicit argument and `ctx`
  as the final positional parameter.
- PEP 696 type-parameter defaults (3.13+) are a syntax error on 3.12, which
  the repo still supports; the 3.13-only dev venv hid it until CI.  Check
  syntax with `python3.12 -m compileall` when using native generics.
- Weak models ignore prompt rules for argument specificity; the robust
  lever is a stronger `tool_picker` model, not more prompt text.
