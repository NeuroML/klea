# Session: 2026-09-11-2130

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective
Diagnose why Klea's opencode Go calls failed after the vendor began requiring
an `x-opencode-session` header, then support models served on non-Chat-
Completions API surfaces (`/responses`, `/v1/messages`) for runtime custom
endpoints.

## Completed
- Confirmed the prior header fix works: `User-Agent` + `x-opencode-session`
  reach the wire via `ChatOpenAI(default_headers=...)` through the real
  `_ConfigurableModel` path. The 500 was not a header problem (missing header
  yields `400 MissingSessionID`).
- Added `resolve_custom_endpoint()` (`klea_utils/llm.py`): a `custom:` URL
  selects the wire API from its path -- `/chat/completions` -> openai,
  `/responses` -> openai + `use_responses_api`, `/v1/messages` -> anthropic;
  a bare base URL defaults to OpenAI Chat Completions (backward compatible).
- Wired the resolver into `LLMModel.build_config`; custom anthropic endpoints
  set `anthropic_api_url` and copy `OPENAI_API_KEY` to `anthropic_api_key`
  (explicit `api_key` override wins).
- Registered `anthropic` in `_PROVIDER_HEADER_BUILDERS` so headers are sent on
  `/messages` too; renamed `_openai_request_headers` -> `_default_request_headers`.
- Log hygiene: `mask_sensitive` masks `anthropic_api_key`/
  `huggingfacehub_api_token`; `_configure_llm` masks the invoke config.
- Packaging: optional `anthropic` extra (`langchain-anthropic`), included in
  `test` (CI) but not `full`.
- Tests: resolver, `build_config` surface mapping, anthropic key copy, header
  and wire-level URL coverage. Agent + RAG example configs use full endpoint
  URLs; docs/AGENTS/CHANGELOG updated.
- Verified: repo ruff clean; 927 passed / 1 skipped (utils non-localonly);
  live opencode calls returned HTTP 200 on `/chat/completions`, `/responses`
  and `/v1/messages` with the session header.

## Errors and Lessons
- An early `import os` addition did not survive into the commit; it was
  re-added later. Check that the committed content matches the working tree.
- Registering `anthropic` as a header provider broke the existing
  `test_other_provider_untouched` (it used anthropic); switched it to
  `mistral`. Run the affected test file after a behavior change, not only
  lint/type.
- Responses-API-only opencode models (e.g. muse-spark) previously 500'd
  because Klea posted to `/chat/completions`. models.dev is not needed: the
  endpoint path is the deterministic source.

## Open Questions
- None blocking. Explicit full-URL custom endpoints were chosen over
  auto-appending paths for known providers.

## Notes
- A bare `custom:` base URL keeps the old OpenAI Chat Completions behaviour;
  users pass the full endpoint to opt into `/responses` or `/v1/messages`.
- The `/messages` surface needs the optional `anthropic` extra at runtime.
