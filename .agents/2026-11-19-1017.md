## Summary

Closed the ADR-0061 scoring-depth gap: the harness now grades a case's
`expected_outputs` and `tool_expectations` deterministically at run time and
records one verdict per check, so scoring grades from stored verdicts instead
of re-reading a run workspace.

## Decisions

- **Checks run at the Execute -> Score handover.** `klea_eval.expectations.check_case`
  runs while the case, the run's `workspace/` and its retained per-turn records
  are all in scope. Each verdict is recorded in the run record as
  `metrics.expectation_checks` beside the derived `task_success` (ADR-0058,
  ADR-0060), and `score_run` grades from those recorded verdicts (ADR-0061)
  rather than re-reading the workspace, keeping the grade reproducible from
  `run.json` and `metrics.jsonl` alone.
- **`file_path` resolves under the run's `workspace/`.** The case directory is
  never read: only what the run produced counts. An absolute or escaping path is
  a failed check and nothing outside the workspace is opened.
- **`validation_rule` is a closed vocabulary** (`exact_match`, `contains`),
  enforced at load time; the ADR's drafted `schema_valid` is a load error.
- **`binary` is a reserved placeholder** with no grading semantics yet, so it is
  rejected at load until a rule for comparing opaque bytes exists.
- **`expected_content` is the rule's operand.** An optional literal text field on
  an expected output; `exact_match` compares the whole decoded file and
  `contains` looks for it as a substring. Without it the rule is `unverifiable`,
  which grades nothing rather than passing by default.
- **Per-tool records are retained** on `TurnMetrics` with name, arguments and
  error; readers accept both the runner's `tool` key and the case schema's
  `tool_name`, so `tool_error_count` derives from the retained records.
- **Docstring review stays open** in `devdocs/backlog.md`; docstrings were
  improved opportunistically on the modules touched here.
