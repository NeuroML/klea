  full stdout/stderr, exit status; no truncation - the UI collapses).
  `download_file` returns a `text/plain` display.  (`044e21f2`, `81e337a3`.)

  each call `running`; the end status replaces it with `ok`/`error` (coarse

### Prompt hygiene (C1)
- pydantic puts a model docstring into the JSON schema, which
  `_format_output_schema_prompt` renders into the system prompt and
  `with_structured_output` sends as `response_format`; ADR/devdocs prose and
  reST leaked to the model.
- Made every LLM output schema **structure-only** (no docstring, no
  `Field(description=...)`; developer prose in `#` comments) across
  agent/rag/utils.  (`01f3e3a8`.)
- Documented as Rule 6 in `devdocs/system/prompt-conventions.md`; per-package
  regression tests.

### Schema strict-safety (ADR-0044 generalised)
- The Evaluator's `evaluations: dict[int, StepEvaluation]` was closed by
  `anthropic.transform_schema` to `properties: {}, additionalProperties: false`
  - the model could only emit `{}` (the ADR-0044 bug, in another node).  Fixed
  by a typed `list[StepEvaluation]` with `step_number`.
- Added `utils_pkg/tests/test_schema_hygiene.py` (AST, repo-wide): discovers
  every LLM output schema and fails on a docstring, a `description=`, or a
  `dict[...]` field; nodes overriding `_get_output_schema` are exempt.
- RAG `RetrievalQueryOutput` rebuilt as a per-run strict-safe schema
  (`klea_utils/stores/query_schema.py`, `build_retrieval_query_schema`): one
  typed optional field per configured filter (`str`/`int`/`float`/`list`, plus
  `IntRange`/`FloatRange` for numeric ranges); `GenerateRetrievalQuery`
  overrides `_get_output_schema` and maps the fields back to operands.
  (`1fdefee3`, `1349151b`.)
- Documented as Rule 7 in `prompt-conventions.md`; ADR-0044 update note.

### Evaluator completion (Model A, goal-authoritative)
- `plan_done` is authoritative for "goal met"; the plan completes only when no
  step is `pending`.  Added a distinct `step_skipped` verdict / `skipped` step
  status for "not needed"; a skipped dependency satisfies its dependents.
- `_validate_result`: `plan_done` with a pending step, or an all-resolved plan
  with no overall, is rejected and retried once via `validation_feedback`.
  Post-retry fail-closed: `plan_done` + pending -> Planner; all resolved + no
  overall -> answer.
- `_update_state` no longer force-closes pending steps.  Schema, evaluator,
  prompts, tests and docs updated (ADR-0035/0041 amendment sections).

### Tool-block UX
- Errored destructive tool results carry `is_error` on the tool entry
  (`tools_caller`), through `MessageData`, to the chat renderer.  Tool blocks
  collapse to a one-line preview (title + first line, expandable) and an
  errored block's title is shown in the theme's negative colour; command
  output/diffs stay hidden until expanded.

## Errors and Lessons

- A Sphinx-mocked import breaks any runtime-evaluated annotation over it;
  re-test each mocked import before trusting a stale conf comment.
- Tool-call errors were silently dropped from the chat (`_display_entry_for`
  returned `None` on `is_error`) while the status pane showed `error`.
- pydantic emits class docstrings as schema `description`s, and strict providers
  close dynamic-key (`dict[...]`) objects to `{}`; both are prompt/schema bugs
  that need deterministic guards, not prompt tuning.
- A schema is a contract its node consumes: changing a field's runtime type
  always forces a (mechanical) node change.
