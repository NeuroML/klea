## Objective
Ship the per-session/per-chat stores config end to end: how a configured stores
file travels from the host app and the TUI `/stores` command through
`ClientContext` and tool-call `_meta` into the bundled `search_stores` tool,
transparently to the tool, plus its precedence, validation and fail-closed
rules. The backend transport is closed and the TUI side is done; web UI
adoption is deferred.

## Completed
- Versioned request-metadata key `klea/stores-config-path/v1` in
  `utils_pkg/klea_utils/stores/utils.py`, so the payload shape can evolve
  without breaking older callers. The value is a single absolute stores JSON
  path, read only in the `search_stores` wrapper from
  `ctx.request_context.meta`.
- Transport plumbing: session config carried in `ClientContext`, sent as
  tool-call `_meta` metadata, and forwarded through MCP dispatch into the
  bundled stores tool.
- Precedence for resolving the stores config, highest first:
  1. a lifespan-reserved value (reserved for server-side wiring, not
     implemented, and not overridable by request metadata)
  2. the request `_meta` payload (`klea/stores-config-path/v1`)
  3. the `KLEA_STORES_CONFIG_FILE` environment variable
  4. otherwise fail closed
- Fail-closed validation: a configured-but-invalid stores path raises
  `ValueError` naming the key and the path and never falls back, so
  misconfigured deployments surface immediately
  (`test_stores_config_resolver.py`). Silent fallback hid configuration
  mistakes.
- Decision: transport the path, not the file contents. Entries are config-file
  relative, the stores must exist on the backend host, the resolved path is
  logged verbatim, and cache keys are `(Path, st_mtime, st_size)`.
- Host default is agent-only: the host app default is wired in the agent
  package config; the RAG app (`rag_pkg/`) is deliberately left unchanged and
  keeps its existing behaviour.
- Developer documentation synced in
  `devdocs/system/stores-domain-search-tool.md` (`a40d3079`).
- TUI chat slot `ChatData.stores_config` (`7f131b83`) and the `/stores` client
  command entry (`fc3d3ca4`).
- `/stores` handler validates locally (usage, no active chat, absolute path,
  missing file, not-a-file); `clear` writes `None`; errors write nothing.
  Identity is passed via the new defaulted `handle_command(user_id, chat_id)`
  (`0fd38d20`).
- `KleaTuiApp._client_context_extra()` merges the slot into a copied context so
  `_meta` carries it on submit, retry and HITL resume; the shared base context
  is never mutated and the existing non-loopback / `--no-client-context` gate
  still sends no payload (`b1ace1d3`).
- No manual respawn code: `client_context_fingerprint` covers `stores_config`,
  so the pooled bundled MCP client re-creates on change.
  `STORES_CONFIG_SERVICE` is left unregistered and reserved.
- Tests: 9 handler tests in `utils_pkg/tests/test_tui_commands_stores.py`,
  plus 4 app tests in `utils_pkg/tests/ui/tui/test_app.py` covering payload
  round-trip, `clear`, `None` base context and retry resend (`c0d7cbf4`).
- Backend commit set: `b2a38f3c`, `399b43fb`, `b697ed8c`, `de219680`,

  behaviour is the safer default for deployment-time config.
