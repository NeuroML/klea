**Authoring agent:** opencode

## Scope

Structured plan status in Klea Agent: the plan pane had to gain a goal line and
step progress text without leaking agent-package imports into `klea_utils` or
changing Klea RAG behaviour.

## Decisions

- Extracted the status payload into an overridable `_get_running_steps_state`
  hook and renamed `_get_running_tools` to match the running-tools entry; the
  base hook keeps only the preformatted `display` fallback and the guard, so
  `klea_utils` still emits nothing when there is no plan or no dispatched step
  number.
- Added `AgentToolsCaller(ToolsCallerNode)` in `agent_pkg` rather than enriching
  the shared base: the structured blocks live in `klea_agent.nodes.plan_content`,
  which `klea_utils` must not import. The subclass overrides only the hook and is
  wired in `klea_agent.py`; Klea RAG keeps the base class and its payload is
  unchanged.
- The plan status now opens with a single truncated `Goal: ...` line (one line,
  bounded to 80 visible characters, ASCII `...`) on both the plaintext `display`
  and the agent-side structured content, so concurrent sessions can be told
  apart at a glance.
- Structured step items now read `Step N/total: summary`, where `N` is the
  dispatched step number and `total` the number of plan steps, so the glyphed
  and plain renderings report the same position instead of the structured view
  dropping progress information.
- Both changes are render-only: no plan write and no persisted `in_progress`
  status. Authoring, advancing and resolving the plan stay with the Planner and
  the Evaluator.
