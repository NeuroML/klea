# Session: 2026-09-19-1946

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Implement the general-path design review: reasoning steps, the
tool-identity contract (planner selects, picker binds arguments), a unified
replan reason, the `needs_input` plan outcome, session-scoped artefacts, and
a cross-package prompt convention.  Work proceeded in small review-and-commit
steps.

## Completed

- **Reasoning steps.** `StepSchema.kind` (`tool` | `reasoning`);
  `StepOutput.result: CallToolResult | str`; new `ReasoningNode` +
  `ReasoningSchema` records a conclusion as a step output and clears stale
  tool calls; `Reasoning -> Evaluating`.  `_planner_router` and
  `_evaluation_router` dispatch the current step by `kind`.
- **Tool-identity contract.** The planner selects a step's tool(s); the picker
  binds arguments only and never substitutes.  Disclosure stays the full
  static catalogue (prompt-cache stability, ADR-0028) with the per-step
  restriction in the prompt.
- **Picker failure handling.** The shared `ToolsPicker` gained an injected
  `on_unusable(state, reason)` callback (mirrors `ToolsCallerNode.post_dispatch`);
  the agent's `_record_picker_failure` records a synthetic `is_error`
  observation and `replan_reason`, and `Selecting tools -> Planning` replaces
  the old empty -> caller -> Evaluator detour.  The picker now sees
  `observations_text()` (all step outputs).
- **Planner output/validation.** `PlannerPlanSchema` with only
  `in_progress | in_review | needs_input | unplannable`; `PlannerOutput.reason`;
  kind/tool and unplannable-with-steps validation; `unplannable` vs
  `needs_input` (partial plan allowed).
- **Replan counter and reason.** `plan_revisions` counts automated replans
  since the initial plan / last human review; the planner links the counter to
  `replan_reason` (non-empty reason => replan), with `in_progress` as a
  fallback.  `evaluation_feedback` was replaced by the unified
  `replan_reason` in prompts.
- **`needs_input`.** New plan status + `pending_question`;
  `AnswerFromResults` third outcome; fixed the pre-existing outcome
  (`Plan failed`/`Plan succeeded`) and double `Failure reason:` label bugs.
- **Persistence.** `artefacts` is session-scoped (no longer reset);
  `artefacts_text()` renders it for the planner; `AnswerFromResults`
  auto-persists the task deliverable (goal-slug keyed, supersede on re-run);
  only the deliverable is session-scoped.
- **Errored-output pruning.** A clean tool round drops the step's earlier
  errored `StepOutput` entries; same-tool arguments-only retry wording.
- **Prompt conventions.** New `devdocs/system/prompt-conventions.md` +
  `BaseLLMNode._optional_section` + `AGENTS.md` pointer.  Audited every node
  prompt and fixed empty-label cases (Planner feedback block, AnswerFromResults
  `outcome_details`, agent picker `picker_feedback`, SummariseMemoryNode
  `old_summary_block`, AnswerFromContext/Evaluator context sentinels,
  Evaluator missing `executed_tools`).
- **Docs/tests.** Updated `devdocs/system/agent-general-path-control-flow.md`;
  CHANGELOG entries; closed test gaps (StepOutput str render + msgpack,
  step-kind router dispatch).

## Errors and Lessons

- **Prompt-cache vs dynamic tool disclosure.** Restricting the picker's tool
  list per step would bust the cacheable system prefix (ADR-0028), so soft
  limiting (static catalogue + prompt rule) was chosen; a deterministic
  substitution backstop is deferred until drift is observed.
- **Duplicated deliberate-vs-glitch predicate.** It is evaluated in both the
  picker node and `_picker_router` because a conditional-edge router cannot
  receive the node's decision, and `replan_reason` is shared with other
  writers (a stale tool-error reason would misclassify a later empty
  selection).  Accepted and documented in the commit message.
- **Lost test on revert.** An early `git checkout` of working-tree changes
  silently removed an uncommitted test (`test_only_deliverable_...`); it was
  later restored.  Lesson: after resetting files, re-check that new tests are
  present and committed.
- **`needs_input` is LLM-decided** and may fire rarely in general mode; a
  step-kind variant was noted but deferred.

## Open Questions

- **HITL interrupt/resume ADR** (next session): generalise `AwaitReview` into

  and state intact (today it terminates with the question; the next turn is a
  fresh run).  Decide whether `needs_input` should also be a step kind.
- **ADR-0041** (parallel step execution, draft): settle the plan-state model,
  the fail-safe dependency default, the picker multi-call allowance, and
  whether to measure the parallelism win.
- **Deferred:** `add_artefact` tool (and promote `_slug`/artefact-id
  derivation to a shared helper or `ArtefactSchema`); phase-2 deterministic
  substitution backstop + planner catalogue-membership validation;
  session-as-invocation / "what next" ADR; cached project explorer.
- `max_plan_revisions` default of 4 now means 4 automated replans (the initial
  plan no longer counts); revisit if a ceiling of 3 is preferred.
