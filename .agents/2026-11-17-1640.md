## Objective
Give a completed eval case that declared rubrics but recorded no grade
(`grade-missing`) its own exit code, so `klea-eval run` and the scheduler surface
it distinctly from a real case failure, which the backlog had left open as a
residual decision.

## Completed
- `klea_eval/pipeline.py`: added the `EXIT_GRADE_MISSING = 4` module constant and a
  `SuiteResult.grade_missing` property that reports whether any considered case
  is completed, declares rubrics (`expects_grade`) and recorded no grade.
  `SuiteResult.exit_code` keeps `0` when every case passed, `1` when a case
  failed its rubrics, and only returns `4` when nothing failed but a case is
  grade-missing; a real case failure still outranks it.
- `klea_eval/scheduler.py`: re-exported the code as
  `EXIT_GRADE_MISSING = pipeline.EXIT_GRADE_MISSING` so a suite-level
  grade-missing result propagates through `ScheduleReport.exit_code` unchanged,
  beside the existing `0`/`1`/`2`/`3` mappings.
- Covered the new behaviour in `eval_pkg/tests/test_pipeline.py` and
  `eval_pkg/tests/test_scheduler.py` (precedence of failure over grade-missing,
  all-passed and all-skipped staying `0`, and scheduler propagation).
- Documentation and tracker updates: `devdocs/system/eval-harness-run-guide.md`
  (run exit-code table), `devdocs/system/eval-harness-implementation.md`
  (pipeline, scheduler and run-label sections), `devdocs/backlog.md` (the
  grade-missing residual decision is now settled) and `CHANGELOG.md`.

## Decision
- `grade-missing` is an operational error, not a rubric failure, so it gets its
  own exit code `4` instead of being folded into `1`; `1` keeps meaning "a case
  failed its rubrics".
- Precedence is explicit: a real case failure outranks a grade-missing case, so
  a suite containing both still exits `1`.
- The scheduler does not invent a new code: it re-exports
  `pipeline.EXIT_GRADE_MISSING`, so the pipeline stays the single definition.
- `Report` is deliberately unaffected, because it reads the run history from
  disk rather than from an exit code.
- Amending ADR-0060's exit-code table (`0`/`1`/`2` -> `0`/`1`/`2`/`4`,
  `devdocs/adr/0060-harness-execution.md:76-79`) is recorded as an open
  follow-up, not part of this change.
