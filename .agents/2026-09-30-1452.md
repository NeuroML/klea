### HuggingFace backend resolution (`utils_pkg/klea_utils/llm.py`)

- New `resolve_huggingface_backend(model_name, suffix)` + constants.  A bare
  `huggingface:<model>` now resolves to the hosted **Inference Providers**
  API (`auto`); `:local` opts into the local pipeline; `:<provider>` selects
  an inference provider; `:cheapest|:fastest|:preferred` routing policies are
  appended to the model id (the HF client's `provider` argument accepts only
  `auto` or a concrete provider name, not a policy).
- `build_config` and `setup_embedding` both use the resolver.
- Consolidated `provider_requires_api_key` + `model_requires_api_key` into one
  public `requires_api_key(model_name)` (accepts a bare provider id or a full
  model string); local HuggingFace is keyless.

## Errors and Lessons

- `ChatHuggingFace.from_model_id` defaults to `backend="pipeline"` (local
  download); with no third segment the picker always hit that default.  The
  real bug was the UI not exposing the third segment, not the catalogue getter.
- HF routing policies (`cheapest`/`fastest`/`preferred`) must be appended to
  the model id; `InferenceClient(provider=...)` accepts only `auto` or a
  concrete provider name.
- models.dev's `huggingface` provider lists only 78 curated (mostly large)
  models; small models (SmolLM2-135M/360M, Qwen2.5-0.5B, ...) are not present
  and must be typed (free text).  models.dev model entries do carry
  `reasoning_options` (the source opencode uses for variants).
- Tooltip clipping came from the global `.q-tooltip { white-space: nowrap }`;
  wrapping fixes it app-wide.
- The local HF smoke test is blocked by a broken `torch` in the maintainer's
  env (`undefined symbol: ncclCommResume`); 8 ingestion/worker tests fail for
  the same reason (unrelated to this work).
