## Objective

Fix the regression from the TUI model-dialog change where a model selection
in one chat appeared to leak into another chat (issue 223), while preserving
the intended "new chats inherit the latest chat's models" default.

## Completed

- Diagnosed the intended model layering: graph/env defaults < per-session
  default ("last used") < per-chat overrides.  Saving in a chat writes every
  shown role as a chat override and promotes only a genuine change into the
  session default, so a new chat inherits the latest selection but a chat that
  saved its own models keeps them.
- Fixed the TUI cross-chat leak: `action_open_models` and `_refresh_models`
  read the mutable `ctx.chat_id` across awaits, so a fetch started for one
  chat could be stored in another chat's cache, and the dialog could combine
  one chat's id with another chat's model info.
- Pinned the chat id when opening the dialog, always fetch its effective
  models afresh, carry `chat_id` in `ModelResult`, store refreshes under the
  requested chat, and repaint the status panel only when that chat is active.
- Reverted an initial approach that stopped TUI promotion entirely; it would
  have broken the intended "new chat uses the latest chat's models".
- Added an API regression test for the layering (new chat inherits, saved chat
  keeps its own, latest save is only the default for unselected chats).
- Updated TUI docs, devdocs and CHANGELOG.

## Errors and Lessons

- The first fix targeted the wrong layer: disabling session-default promotion
  removed the "last used" behaviour the product relies on.  Clarifying the
  intended semantics first avoided landing that regression.

## Open Questions

- API keys remain provider/user-scoped (ADR-0042), not per-chat; the issue text
  mentions chat-specific keys, but that is a separate design change.
- Existing session defaults promoted before this fix remain in the database;
  they are legitimate defaults now, not purged.
