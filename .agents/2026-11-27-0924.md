# Session log: per-model token usage ledger

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash

## Inspection pane: stray `{}` fixed

- **Root cause:** an inspect entry's `details` mapping carried `NodeStreamData`'s own empty nested `details: {}` field. The renderer-side filter was necessary but not sufficient: the nested container key `details` itself was not listed in `NOT_DISPLAYED_DETAIL_KEYS`, so the empty mapping still reached the output even once the renderers filtered through `drop_not_displayed`.
- **Fix:** the nested `details` key was added to `NOT_DISPLAYED_DETAIL_KEYS` in the shared filter (`ui/inspect_format.py`), so `drop_not_displayed`/`format_details` strip it wherever it appears; in addition, the web (`ui/web/nicegui/components/inspector.py`) and TUI (`ui/tui/components/inspector.py`) renderers filter with `drop_not_displayed` before `format_details`, mirroring `status_pane.py`, and the TUI's existing "(no details)" fallback covers a fully filtered body.
- **Tests:** the targeted web and TUI inspector test modules plus the shared inspect-format tests pass after the corrected fix.

## Objective

Replace the single thread-level `usage_metrics` token counter in the shared graph
state with an authoritative per-model token ledger (`token_usage_ledger`), so
token cost can be attributed per model as well as summed for the whole thread.

## Completed

- Recorded the decision in ADR-0056: `usage_metrics` is deleted outright rather
  than kept as a deprecated mirror, because the agent is unreleased, the shared
  packages are pre-1.0 with no backward-compatibility promise, and no external
  consumer or entitled data exists. The ledger is the authoritative channel.
- Added `TokenUsageLedger` (`by_model: dict[str, TokenUsage]`, `total()`,
  `total_by_model()`) and the `add_usage_ledger` reducer that unions model keys
  and accumulates per-key totals.
- Swapped the state field to `token_usage_ledger: Annotated[TokenUsageLedger,
  add_usage_ledger]`, and the node writer to `_update_usage_ledger`, keyed by the
  node's effective model string with an `unknown` fallback.
- Context endpoint still returns the flat `usage` total, now folded from the
  ledger, so hydration restores the session total. A thread checkpointed before
  the change reports no token totals; the stale key is ignored on read.
- Updated code, tests (utils, agent, rag), CHANGELOG, devdocs, user docs and
  ADR-0056. Per-model display in the web UI and TUI is deferred to the backlog.
- Lint, type check on touched files, and the targeted test suites are green.

## Errors and Lessons

- Several edit anchors did not match the source and failed, forcing repeated
  re-reads of the same file regions. Always read the exact current text of an
  anchor before binding an edit; never assume a remembered line.
- A partial substitution left the ledger assignment mis-indented and outside its
  `if`, which broke the block and then showed up as a type error (`Self` lacking
  `_effective_model_name`). Fix the indentation and the type together, then
  re-check.
- Confirm the class that owns a helper before calling it: the model-name
  accessor lives on the file-based node base, not on the abstract LLM node that
  writes the ledger.

## Stray `{}` in rendered details (fix record)

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash

- **Root cause:** empty container values survived the not-displayed-key
  blacklist. A filtered `details` mapping could still hold a nested empty `{}`
  (for example a tool call's empty `arguments`), which then reached the
  rendered body as a bare `{}`.
- **Fix (commit b77b3ffd):** `visible_details` and `format_details_block` in the
  shared `ui/inspect_format.py` prune empty containers after filtering, and both
  inspector renderers (web and TUI) go through those helpers instead of
  re-implementing the filter, so neither frontend can emit an empty `{}` block.

## Per-model token usage in the status panes

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash

- **Why the live stream cannot supply it:** the streamed `usage` event is a
  projection of one node's own calls and carries no model identity, so nothing
  in it can be attributed to a model. The breakdown is hydration-sourced only.
- **Data path:** `token_usage_ledger` (ADR-0056) is checkpointed state; the
  context endpoint keeps the flat `usage` total from `ledger.total()` and adds
  the per-model split as `usage_by_model` -- per-model `TokenUsage` dumps keyed
  by model name, `None` when the ledger is absent.
- **Shared formatter:** `format_token_usage_by_model` in `klea_utils/ui/state.py`
  maps `usage_by_model` to ordered `(model, line)` rows through the existing
  `format_token_usage`, so both frontends render identical text.
- **Web:** the status pane keeps the thread total line and, when rows exist,
  wraps it in a collapsible `usage-group` expansion (open state bound to
  `ctx.status_usage_expanded`, independent of the models group) with one row per
  model.
- **TUI:** the status panel renders the thread total followed by one row per
  model, in the fixed header above the scrolling state sections.
