## Objective

## Completed
- Session picker scroll fixed: `#sessions-list` used `height: auto; max-height: 16;`, which Textual treated as a cap rather than a viewport, so entries below the fold were unreachable. Changed to a bounded `height: 16` plus `scrollbar-size-vertical: 1`, giving the ListView a real viewport so every session stays reachable. Commit `e5acc2bd fix(tui): make the session picker list scrollable` (`sessions.py`, `devdocs/system/tui.md`).
- Confirmed the TUI/web session-count discrepancy was the same needs-scroll issue, not a capped fetch: the client and DB layers apply no `LIMIT` (`GET /chat/{user_id}` -> `list_chats`), so no data-layer change was made.
- HITL field visibility fixed: `HitlDecisionPanel Input` and `QueryTextArea` relied on Textual's near-invisible default `$border-blurred` on `$surface`, and the review field forced `border: none`, so fields read as blank until focused. Added a permanent `border: tall $primary 40%` with `background: $primary 15%`, plus a scoped `:focus` rule brightening the edge to full `$primary`. The chat composer and `#rename-input` were left untouched. Commit `7a4c2f19 fix(tui): make HITL input fields visible when unfocused` (`hitl.py`, `devdocs/system/tui.md`).
- TUI message footer fixed: each `MessageBlock` closed with the overflow hint (`Enter/click to expand | drag to select`) on one row and the `stamp` on the row below. Both now share a single footer row (`Horizontal.message-footer`, `height: 1`): the hint is content-sized on the left and only displayed when the body overflows, and the stamp takes the rest of the row (`width: 1fr`, `text-align: right`) so it stays right-aligned whether or not the hint is present. The hint's `display` gate, `can_focus` overflow test, click-to-toggle and `SelectableStatic` selection are unchanged, and both widgets keep their `.message-more` / `.message-stamp` query targets.
