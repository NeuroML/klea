### File-tool hardening (`read_file` etc.)

- `read_file` paging/truncation contract rewritten: `line_end` is the last line
  actually returned; a truncated read is a success carrying
  `next_offset`/`note`; a single over-long line pages by
  `char_offset`/`next_char_offset`; a non-positive `limit` reads one line
  (previously the whole file); an offset past EOF is explained.
- Character budget is now server-owned (`_MAX_CHARS`; `max_chars` removed from
  the tool schema); default page 500 lines.
- Plain text is strict UTF-8 with BOM stripping; binary (NUL) and invalid UTF-8
  are refused; the read is bounded (`_read_bounded`) so a file that grows
  mid-read cannot exceed `max_bytes`.
- Shared line definition `file_ops.split_lines` (LF after CRLF/lone-CR
  normalisation; trailing newline is not a line; form feeds/Unicode separators
  are not breaks) used by `read_file` and `grep`, which now also uses the
  shared `is_binary`.
- `check_path_access` denies an unresolvable target (e.g. a symlink loop)
  instead of crashing; hard-link and TOCTOU containment limits documented.
- New `devdocs/system/file-tools.md` (contract + edge-case matrix), registered
  in `devdocs/README.md` and the `AGENTS.md` code -> devdoc map, cross-linked
  from `mcp-permissions.md`; backlog items for streaming paging and the
  containment limits.

## Errors and Lessons (later work)

- `read_file`'s `line_end` was computed before the `max_chars` cap, so a
  truncated read reported the full slice end and looked complete; the cap now
  applies to the rendered text at line boundaries with an explicit continuation.
- Python's `str.splitlines()` splits on form feeds and Unicode separators,
  disagreeing with editors/`wc -l`/`edit_file`; replaced by a shared `\n`
  definition.
- `Path.resolve()` (non-strict) **swallows** a symlink loop (ELOOP) and returns
  the path as-is on this Python; use `resolve(strict=True)` with a
  `FileNotFoundError` fallback so missing targets still yield nearby entries.
- Symlink dirs are already skipped by `walk.iter_files`, so the loop risk was
  only in `check_path_access`.
- The user flagged that models use every tunable parameter, so the read size is
  enforced server-side (a hidden budget) rather than by a default alone.

## Task 1: concurrent chats in one page (continued 2026-10-08)

### Objective

Let each chat in one web page run its own graph session at once.  The server
already allows concurrent per-thread runs (`ActiveRunRegistry` keyed by
`thread_id`), so this was frontend-only: the page-global run state on
`PageContext` blocked it.

### Design

- Per-chat run registry on `PageContext`: `stream_tasks` / `retry_cbs`, keyed
  `f"{user_id}:{chat_id}"` (matching the `chats` store key, so a
  delete-user-session `user_id` reset cannot collide).  `chat_is_streaming`
  reads the registry; `ChatData["turn_status"]` stays the *display* state
  (spinner / error / Retry / HITL form), not the run signal.
- Task handles stay page-scoped (asyncio tasks are loop-bound; `chats` is
  process-global/shared across tabs).  Callers register the created task right
  after `background_tasks.create(...)` so gating is race-free; `run_stream`
  clears its entry in `finally` but keeps the retry callback.
- Render isolation: `run_stream` always updates `ChatData`, but only touches
  the DOM when the run's chat is active (`_active()` guard); the live
  turn-status label is never written for a background chat.
- Message expansion (`ChatData["expanded"]`) moved off `PageContext`.

### Errors and Lessons

- `turn_status` is a display state, not a run signal; deriving "is streaming"
  from it conflates concerns.  Use the chat-keyed task registry.
- Register the task in the *caller* (from `background_tasks.create`, which
  returns the `Task`) rather than inside `run_stream`, to close the
  send/start race.
- NiceGUI `user.should_see` returns immediately when the element is already
  present (no implicit yield), so a test asserting a *background* run started
  must `await asyncio.sleep(...)` first.  Also, a blocked send leaves the typed
  text in the input box, so a "not sent" assertion must clear the input.
- `ui.item` has no text, so content-based `find` does not match it; the
  chat-list "New Chat" control carries `.mark("new-chat")` for the test.
