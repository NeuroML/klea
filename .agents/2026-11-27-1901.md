# Session: 2026-11-27-1901

**Authoring agent:** Klea

## Objective
Remove the doubled horizontal line above the plan in the terminal status panel,
so the fixed usage area and the scrolling state sections are separated by a
single line instead of two.

## Completed
- Traced the doubled line to two independent sources, not one duplicated rule:
  the fixed block closes with the `status-divider` `Rule` (last child of
  `#status-fixed`, mounted right after the usage group), and the state-section
  `Collapsible` widgets each paint Textual's default top keyline
  (`border-top: hkey $background`).  The first section in `#status-scroll` sits
  under both, so the pair reads as one doubled separator.
- Confirmed the affected surface is the TUI pane only: the web status pane draws
  its group divider with `ui.separator()` and is not affected.
- Chose to keep the `status-divider` Rule as the single closer of the static
  usage area (it is fixed and never scrolls) and to suppress the top keyline on
  the first state-section collapsible only, via a `:first-of-type` rule added to
  the existing `border-top: none` selector group in the `StatusPanel`
  `DEFAULT_CSS` block of
  `utils_pkg/klea_utils/ui/tui/components/status_panel.py`.  Later sections keep
  their keyline, so they still separate from one another (N sections give N-1
  separators), and the fixed divider is untouched.
- Verified the mechanism before relying on it: the pinned Textual is 8.2.8 and
  `first-of-type` is a supported structural pseudo-class there
  (`css/constants.py:78`, `css/stylesheet.py:460`, and the structural set at
  `css/stylesheet.py:509`).
- Checked the widget/CSS contract so the change does not fight the reconcile
  logic: `_section_widget` always builds collapsibles with
  `classes="status-section"`, and `_reconcile_sections` keeps mounted widgets
  when their content signature is unchanged, so a CSS-only rule applies to a
  reconciled pane without extra state.
- Recorded the fix under `Fixed` in `CHANGELOG.md`.
- Documented the invariant in `devdocs/system/tui.md`: exactly one `status-divider`
  closes the fixed usage area and the scrolling state sections begin directly
  after it with a single separator.
- Extended the regression coverage in `utils_pkg/tests/ui/tui/test_app.py` with
  `test_status_panel_single_separator_above_first_section`, which asserts the
  first section draws no keyline while later sections keep theirs.

## Errors and Lessons
- The duplicate line looked like a doubled CSS border.  It is two different
  widgets drawing two different lines; reading the compose order
  (`#status-extras`, `#status-fixed`, `#status-scroll`) first points at the
  boundary immediately.
- The first state section is the only one that both follows the fixed divider
  and draws a keyline, so the rule must be scoped to the first section, not to
  `.status-section` broadly: clearing it for all sections would merge adjacent
  sections with no separation.
- The CSS-only route was preferred over stamping a class in
  `_reconcile_sections`: it needs no widget state and survives the in-place
  reconcile.  Trade-off: it relies on `:first-of-type` resolving against the
  section collapsibles (supported in the pinned Textual 8.2.8).
- The regression test must populate `model_info` and the usage totals first: the
  closing `status-divider` Rule is only mounted when the fixed block carries
  content, and without it there is no duplicate separator to assert against.
  The first pytest attempt failed for exactly that reason.
