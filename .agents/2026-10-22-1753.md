## Objective

Remove the lightweight CLI/REPL, fix path-permission detection and approval
display, and add a reusable state-edit HITL mechanism with a `/paths` command
for managing session-scoped path approvals.

## Completed

- Removed the `cli` subcommand and `input()` REPL (`ui/tui/repl.py`), the
  REPL tests, and the `yaspin` dependency. Bare `klea` / `klea-rag` launches
  the Textual TUI; `tui` and `web` remain explicit. Added `tui` extras to the
  agent and RAG packages and to their `full` extras.
- Retained the opt-in `agent_pkg/e2e` harness (restored its markers) but
  annotated it as needing retargeting to `klea-serve` plus HTTP/SSE; it still
  references the removed `klea cli --single-query` entry point.
- Path detection: added `split_shell_tokens()` using shlex punctuation mode,
  keeping comments disabled and `whitespace_split=True` for Windows drive
  paths. Shell operators no longer cling to paths; quoted command
  substitutions are still unwrapped.
- Permission asks now collect `covered_paths`, merge coverage across calls in
  the same directory, show a `Covers` list in web/TUI, always show the
  detected token for `value:` guesses, and use a shorter token-centred preview.
- Added a generic `state_edit` HITL helper and payload (`StateField`,
  `StateEditRequest`, `StateEditResponse`, `edit_state_fields`) plus web and
  TUI renderers for `path_list`, `text`, `bool` and `select` fields.
- Added `/paths [list|add <dir>|remove <path>]`; bare `/paths` opens the
  state editor for `allowed_dirs` (add/remove) and `allowed_files` (remove
  only). Validation rejects non-directories, paths inside the project root,
  and the project root itself; parent coverage is reported.
- Moved the reusable path-approval helpers to
  `klea_utils/mcp/path_approval.py`; the agent command now only parses and
  formats command-specific messages.
- Docs synced: session-commands, commands.rst, mcp-permissions, ADR-0007,
  streams, TUI, mcp API reference, backlog and CHANGELOG.

## Errors and Lessons

- `shlex.split` already uses `whitespace_split=True`; the missing piece for
  shell commands was `punctuation_chars`. Do not enable `commenters`: it
  treats `#` anywhere as a comment and truncates paths like `foo#bar`.
- Quoted command substitutions (`"$(wc -l < /tmp/x);"`) are not split by
  punctuation mode, so a small cleanup is still needed for the wrapper.
- A state-edit response with no changes must not emit empty state updates;
  only changed `allowed_dirs`/`allowed_files` fields are included.

## Open Questions

  It supports batch removal and addition, which was the requested use case.
