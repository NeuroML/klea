# Session: 2026-10-22-1528

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Fix the answer-node structured-output fallback that discarded a valid prose
reply, replace the tool-results fallback with the plan, and stop truncating
notice content in the TUI/web UIs.

## Completed

- Root cause: the model returned the answer as prose instead of the requested
  `{"answer": ...}` envelope. `JsonOutputParser` failed, `repair_json` returned
  `""` for prose, and the handler re-parsed `""`, raising a second
  `OutputParserException`. `_parse_structured_message` then returned
  `AnswerSchema()`, and `_update_state` fell back to `textualize_tool_results`.
- `AnswerFromResults._get_default_error_result` now recovers non-JSON prose from
  `ctx.output` (strips a `</think>` prefix, ignores blank and broken-JSON
  content) as the answer.
- `AnswerFromResults._fallback_answer` now renders a conditional outcome
  sentence plus `state.plan.render()` instead of tool results.
- `AnswerFromContext._get_default_error_result` applies the same prose recovery
  (`references=[]`) and keeps its retry message for blank/broken JSON.
- `parse_output_with_thought` only re-parses when `repair_json` returns
  non-empty text; otherwise it re-raises the original parse error.
- Removed the 1000-character hard truncation in
  `AbstractLangGraphNode._emit_notice`. The TUI and web UI still collapse long
  notices and let the user expand them.
- Tests added/updated: agent prose recovery and plan fallback, RAG prose
  recovery, parser repair/re-raise, and full-length notice emission.
- Docs synced: `devdocs/system/structured-output-fallback.md`,
  `devdocs/system/tui.md`, `devdocs/system/streams.md`.

## Errors and Lessons

- `repair_json` only repairs malformed JSON; it does not wrap prose into the
  schema envelope (verified: prose -> `""`).
- `_get_default_error_result(ctx)` has access to the raw output, so a free-text
  answer node can recover it without touching the shared parser.
- Re-parsing inside an `except` block can replace the original, informative
  exception with a second, emptier one. Guard the repair path.
- The notice truncation was server-side in the shared node base, so it affected
  both frontends; the UIs already had collapse/expand.

## Open Questions

- Free-text answer nodes still pay a structured-output attempt and a parse
  failure before recovery. Converting them to non-structured nodes (like
  `AnswerGeneral`) would remove that, but changes prompts and tests.
- Broken JSON-like output is not recovered. A targeted salvage of an `answer`
  field from near-JSON could be added if it recurs.
