## Goal

Implement the ADR-0059 retention policy as an archive tier instead of a hard
delete: a run beyond the per-case window keeps its record files and index line,
and only its workspace tree is reclaimed.

## What changed

- Retention (`api.apply_retention`, `DEFAULT_RETENTION = 20`) now archives an
  older completed run by default: its `workspace/` tree is removed while
  `run.json`, `metrics.jsonl`, the `COMPLETE` marker and its
  `runs/index.jsonl` line survive, and a zero-byte `ARCHIVED` marker is written
  beside them.
- `purge=True` keeps the previous behaviour: delete the whole run directory and
  drop its index line. `dry_run=True` reports the plan without touching disk.
  A second archive pass over an already archived run is a no-op.
- Workspace helpers expose `ARCHIVED_MARKER_NAME`, `is_archived` and the
  `RunState.ARCHIVED` state; the API (`get_run`, `list_runs`, `suite_summary`)
  and `klea-eval check` treat an archived run as a legitimate complete run.
- The CLI `klea-eval prune` gained `--purge` and `--dry-run` and reports kept,
  archived and pruned counts.
- Tests updated and added: `tests/test_api.py`, `tests/test_retention_archive.py`,
  `tests/test_workspace.py`, `tests/test_consistency.py`, `tests/test_pipeline.py`.

## Rationale

Other evaluation harnesses separate cheap metadata from bulky artifacts so
results stay comparable long after a run: keeping the record and dropping the
workspace preserves debuggability and aggregation at a fraction of the disk
cost. Destruction stays an explicit opt-in (`--purge`), never the default.
