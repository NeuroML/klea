## Changes

1. Spinner lifecycle (`ui/tui/app.py`, `ui/tui/components/turn_status.py`):
   `_run_query` stops the turn spinner unconditionally in its `finally`
   through a new `TurnStatus.stop_spinner()`, so a stream that ends with no
   terminal event cannot leave the timer running. `stop_spinner()` tears down
   only the timer and leaves the status label intact, so an error or an
   awaiting-input note is not clobbered.
2. Approval previews (`mcp/path_detect.py`): `_recover_anchor` recovers a
   locatable fragment (the stripped token, then its basename) when the
   normalised token is not a literal substring, and `_preview_details`
   centres its window on that anchor. This stops a detected token being
   hidden by a head truncation.
3. Status panel (`ui/tui/components/status_panel.py`): `_section_signature`
   plus an attribute stamp let `_reconcile_sections` keep an unchanged
   section mounted instead of rebuilding every section on every streamed
   event. The per-tick re-render cost during streaming was the reason for
   the change.

## Web transcript: scroll paging and in-place expand

**Authoring agent:** Klea
**Model:** opencode-go:deepseek-v4.1-flash

- Bounding answer: both transcripts are bounded on every path.  The web UI
  bounds by a single `MOUNTED_MESSAGE_LIMIT` (80) applied in
  `_render_messages`, which every path reaches (session resume
  `initial_load.py:127`, live append `input_area.py:189` /
  `commands.py:622`, event/expand `stream.py:211`/`:226`).  The TUI bounds by
  its hydration window `WINDOW_SIZE` (40) plus the live cap `MAX_MOUNTED`
  (80) with `SCROLL_BATCH` (20) for paging
  (`tui/components/transcript.py:285-289`, `_mount_newest`, `_evict_oldest`).
- Expand jump: `on_expand` called `ctx.render_chat_area()`, whose
  `ctx.chat_area.clear()` collapsed the scroll extent and reset the
  viewport; the same-set scroll guard only gates the explicit scroll-to-
  bottom, so it could not prevent it.  Fix: the expand toggle now flips the
  bubble's collapsed class and toggle icon in place
  (`_apply_bubble_collapsed`) and records the choice in the chat's `expanded`
  set, so no rebuild (and no jump) happens -- the same in-place approach the
  TUI uses (`MessageBlock.action_toggle_expand`).
- Scroll paging: mirrors the TUI.  New `SCROLL_BATCH = 20`; the mounted
  window's first index is kept per chat in `PageContext.mounted_start_by_chat`
  (defaulting to the newest window on a switch or new message); a browser
  scroll listener emits `klea_scroll_top` / `klea_scroll_bottom`;
  `_page_older` lowers the start by a batch and restores the reader's offset
  on the previously-top bubble, `_page_newer` raises it and pins the bottom.
  The window stays bounded by `MOUNTED_MESSAGE_LIMIT` and the store is never
  trimmed; `loading_older` / `loading_newer` and `scroll_paging_until` guard
  re-entrant paging from the rebuild's own scroll event.
- Docs: `devdocs/system/tui.md` now describes the web paging and the in-place
  expand; `CHANGELOG.md` (Unreleased) records the paging under `### Changed`
  and the expand fix under `### Fixed`.
- Tests: new `tests/ui/web/test_chat_area_scroll.py` (in-place expand keeps
  the scroll offset; paging mounts older then trims, then re-mounts newer,
  contiguous and bounded).  `python -m pytest tests/ui/web -q` -> 27 passed;
  `ruff check .` clean; `ty check` at the 39-diagnostic baseline.
