## Completed

- **Issue 1 -- status panel did not refresh on context change.**  The
  `StatusPanel` only rebuilt its `status_extras` on the initial mount, so
  mode/access changes made after startup were not reflected.  Fixed by
  rebuilding the extras on every `context` change in
  `ui/tui/components/status_panel.py`; the shared `SubmitQuery` message path
  was left untouched.
- **Issue 2 -- `/exit` left the active run dangling.**  `_exit_after_stop`
  stopped the run via `action_stop` but could return before the worker had
  actually unwound, so the app exited mid-stream.  Made the stop awaited and
  the exit scheduled only after the run is confirmed stopped in
  `ui/tui/app.py` (`EXIT_APP_SERVICE`).
- **Issue 3 -- model dialog did not re-fetch `model_info` on a
  credential-only change.**  `ModelResult.changed` was not propagated when
  only API keys changed, so the dialog showed stale role state.  Fixed in
  `ui/model_config.py` and `ui/tui/components/model_dialog.py` so a
  credential-only change re-fetches `model_info`.
- **Issue 4 -- sessions picker delete did not purge the checkpoint.**  The
  TUI delete path called `store.delete_chat` but skipped the LangGraph
  checkpoint purge that the web path performs.  Aligned the TUI with
  `api/sessions.py` `delete_chat` (cancel active run, then
  `checkpointer.adelete_thread(thread_id_for(...))`, then
  `store.delete_chat`) in `ui/tui/components/sessions_picker.py`.
- **Issue 5 -- user input was Markdown-mangled in the TUI transcript.**
  Literal underscores, `#` and single newlines were being rendered as
  Markdown.  Routed user messages through the verbatim/`linkify_html` path
  (already used by the web) in `ui/tui/components/chat_area.py`, keeping
  agent/system messages Markdown and tool messages MIME-based.
- **Deferred `/inspect`.**  The `/inspect` backlog item was intentionally
  deferred to a future session; recorded in `devdocs/backlog.md` rather than
  implemented here.
- **devdocs sync.**  Updated `devdocs/system/tui.md` to describe the status
  panel refresh, the `/exit` stop-then-exit ordering, the credential-only

- **Tests.**  Updated the TUI pilot tests under `utils_pkg/tests/ui/tui/`

## Errors and Lessons

- **Never `await` a `@work` method** -- it returns a `Worker`, not an
  awaitable.  The `/exit` fix had to make the stop a plain `async def` run
  via `run_worker` (or fire-and-forget) rather than awaiting the worker.
- **Test harness import-time binding**: patching `klea_utils.api.sse.*` /
  `klea_utils.ui.client.*` does not rebind names imported *into* component
  modules; the `fake_backend` fixture must patch the component modules' bound
  names too (`ui.model_config`, `ui.tui.components.*`).
- **`ty` reports stale/noise diagnostics**: unresolved `textual` imports and
  `klea_utils.ui.client has no member <fetcher>` are pre-existing; filter
  with `ty check | rg -v "<known noise>"` rather than trusting the LSP.
- **Environment**: this venv's editable `klea_utils`/`klea_agent` point at
  the sibling `.../software/klea` (development) repo, so utils tests are fine
  (cwd shadows) but agent/rag tests resolve the other repo; verify them with
  `PYTHONPATH=.../klea-tui/utils_pkg`.
