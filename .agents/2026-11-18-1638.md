## Task

Clarify the approval (path-permission) prompt's step groups in both frontends, so a
long or multi-path ask stays readable without the prompt changing height.

## Changes (four readability improvements)

1. **Capped, wrapped step headings.** A `Step N: summary` heading that would
   overflow now wraps onto at most two lines of 76 characters and is cut with an
   ASCII `...`.
   - TUI: `PermissionPanel._wrap_heading`, plus the `STEP_HEADING_MAX_LINES` /
     `STEP_HEADING_WRAP_CHARS` constants; the heading and its notes stay on one
     markup-free Rich `Text`.
   - Web: `_wrap_permission_heading`, plus
     `MAX_PERMISSION_STEP_HEADING_LINES` / `MAX_PERMISSION_STEP_HEADING_LINE_CHARS`;
     the heading classes gained `whitespace-pre-line` so the breaks survive.
2. **One muted coverage line per step group.** `_group_coverage` (TUI) and
   `_permission_group_coverage` (web) count a group's requests by `kind`:
   `N paths: X outside the project, Y sensitive`. The noun is singular for one
   path, zero-count categories are dropped, and an unknown/missing `kind` counts
   in a trailing `unknown` bucket only when non-zero.
3. **`Also serves step N` emitted once per group.** `_group_also` /
   `_permission_group_also` union the further steps of every multi-step request,
   sort and de-duplicate them, and render a single line beneath the group
   heading; the per-row hint was removed from both `compose` and the web rows, so
   a path row can never repeat it.
4. **Dividers between adjacent step groups (web).** The refreshable `_rows`
   draws one `ui.separator()` between adjacent step groups and never before the
   first or after the last; the existing `gap-2` supplies the surrounding
   spacing and no new CSS class or token was introduced.

## Deliberate non-implementation: sticky heading

A sticky/pinned step heading was **not** implemented. It would need per-scroll
reflow inside a panel that must keep a fixed height, which conflicts with the
shared HITL grammar (ADR-0046, ADR-0007), so the heading stays inline with its
group. This is recorded in `devdocs/system/mcp-permissions.md` and
`devdocs/system/tui.md`.
