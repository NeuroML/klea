# Session: HITL ask sections show their payload title once, without an "Option N" prefix

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash
**Date:** 2026-11-18 17:48

## Goal

The review/input HITL ask showed section headings incorrectly. Multi-section asks
prefixed every section header with a synthetic `Option N` label, and in the TUI a
multi-section ask rendered each title twice: once as the Collapsible header and
again as an inner static. The headings should be exactly the backend's payload
titles, shown once.

## Decisions

- Render each section's payload `title` verbatim in both frontends, with a
  `Details` fallback when the title is empty or whitespace-only.
- Drop the synthetic `Option N` prefix entirely; the payload title is the only
  heading text.
- TUI: a single-section ask renders a plain bold heading plus its body; a
  multi-section ask uses the Collapsible header for the title and does not
  re-add it as an inner static, so the title appears once.
- Keep the existing multi-section behaviour of first section expanded and the
  rest collapsed.
- Leave the permission and state_edit panels untouched; their numbering is a
  separate, purposeful scheme.

## Changes (high level)

- `utils_pkg/klea_utils/ui/tui/components/hitl.py` - verbatim titles, single
  vs multi-section rendering, no duplicated title widget.
- `utils_pkg/klea_utils/ui/web/nicegui/components/chat_area.py` - verbatim
  titles, no `Option N` prefix, always render the heading.
- Tests: a new TUI test covering multi-section titles (verbatim, `Details`
  fallback, rendered once) in `utils_pkg/tests/ui/tui/test_app.py`, and an
  assertion that no `Option ` label appears in the web review ask in
  `agent_pkg/tests/ui/web/test_chat_flow.py`.
- Docs: `devdocs/system/tui.md` section-titles rule and the plan-history
  wording updated; `CHANGELOG.md` entry added under Unreleased / Changed.
