### Evaluator route-override fix (regression from `9386f8ba`)
- Root cause: `9386f8ba` ("remove double `k` increment") removed the router's
  `_increment_k(...)` while `RetrieveInfoNode` still gated on the raw
  `next_step == "retrieve_more_info"`.  So when the router chose
  `retrieve_more_info` from its score heuristic (`coverage >= 0.5 and
  confidence < 0.5`) with a different verdict, `k` never grew.  The same
  class of mismatch affected `modify_query` (k grew when it should not),
  `rewrite_answer` (`rewrite_attempts` never advanced) and `best_effort`
  (warning suppressed).
- Fix: added `RAGState.route` (the effective decision, distinct from the raw
  `next_step`) and documented the distinction. (`4dfcf37b`.)
- Converted `RouteEvaluator` into a full state-updating node that records
  `route`; added a thin `RouteDispatcher` (`AbstractRouterNode`) and rewired
  `rag.py` evaluate -> route node -> conditional dispatch. (`f8bf7416`.)
- Action nodes now read `route`: `RetrieveInfoNode` grows k on
  `route == "retrieve_more_info"`; `AnswerFromContext` bumps `rewrite_attempts`
  on `route == "rewrite_answer"`; `AnswerUser` warns when
  `route != "continue"`. (`d1aec352`.)
