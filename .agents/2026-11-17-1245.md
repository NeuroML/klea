# Session: 2026-11-17-1245

**Authoring agent:** Klea (tool-call binder for planned steps)
**Model:** opencode-go:deepseek-v4.1-flash

## Objective
Add display-only plan-step context to the client-side path-permission ask, so the user can see which plan step each requested path serves, without changing any permission semantics.

## Completed
- Added `StepRef` (step_number, summary), `PathRequest.steps`, `MAX_STEP_SUMMARY_CHARS` / `MAX_STEP_REFS`, and the `bounded_step_summary` / `normalise_step_refs` helpers in `klea_utils/mcp/path_detect.py`.
- Added the `step_summaries` keyword to `dispatch_tool_calls`; each detected request is stamped with the step its call serves, and `_dedupe_requests` unions step refs by step number.
- Hoisted a bounded, de-duplicated, step-ordered top-level `steps` list into the permission payload in `klea_utils/mcp/permission_hitl.py` (per-request `steps` arrive via `model_dump`).
- Added the optional `step_summary_getter` kwarg to the shared `ToolsCallerNode` and passed its result through to dispatch.
- Moved the step-summary derivation onto the plan schema as `PlannerPlanSchema.step_summaries()` in `agent_pkg/klea_agent/schemas.py`, so the general plan functionality is reusable by other nodes; `agent_pkg/klea_agent/nodes/agent_tools_caller.py` now keeps only a duck-typed adapter that passes the result through to dispatch (klea_utils cannot import klea_agent, so it still arrives as an injected callable). Klea RAG supplies nothing, so its asks stay step-free.
- Rendered one bounded `Step N: summary` line per entry (plain labels / `markup=False`) in both the web and TUI permission forms, rendering nothing when the list is absent.
- Added tests for payload present/absent, de-duplication, capping, summary bounding, and the TUI/web rendering helpers.
- Documented the fields and caps in `devdocs/system/mcp-permissions.md` and `devdocs/system/streams.md`, and added a CHANGELOG entry.

## Errors and Lessons
- No failed tool calls this session; existing observations (file contents, paths) were reused rather than re-read.
- Keeping permissions fail-closed required the new context to be purely display-only: decisions still key on `path`/`directory`, and a missing plan yields an empty `steps` list rather than an error.

## Open Questions
- Whether the step context should also appear in the inspect audit entry for a resolved ask (currently the chat forms only).

## Notes
- Design constraints honoured: `klea_utils` must not import `klea_agent`, so the plan-to-summary mapping is injected as a callable; step summaries never enter prompts, tool arguments or MCP `meta`.
- Bounds: each summary is whitespace-collapsed and cut at 160 characters with an ASCII `...`; at most 8 step entries are carried.
