## Objective

Add tracing/attribution metadata to the streamed events so an evaluation
harness can trace and attribute them: node/run identity, a per-node LLM-call
count, and the tool-call attempt number.

## Completed

- Stamped event identity once, in `run_graph_astream_events` (`_stream_identity`
  in `utils_pkg/klea_utils/graph/base.py`): `node_id`, `run_id` and `step` on
  the node-scoped events, `run_id` only on `context`/`complete`, all additive.
- Added `llm_calls` to `LLMNodeContext` and the `usage` details; usage stays
  per node execution and the turn-level totals are documented as aggregates.
- Emitted `retry_count` (the pre-existing 0-based `tool_retry_counts[step]`
  count, already in the triage inspect payload before 064380d7) on `tool`
  entries and the tools caller's/triage router's `inspect`/`state` payloads;
  the added `try_number` was dropped as a duplicate (consumers add one for an
  attempt number).
- Deliberately omitted `call_id` from `ToolCallSchema`.
- Added/extended tests in `utils_pkg` (graph base, tools caller, node schema)
  and `agent_pkg` (triage router).
- Updated `devdocs/system/{streams,api-sse-sequence,agent-node-contracts}.md`
  and `CHANGELOG.md`; `docs/` needed no change.

## Notes

- Identity is stamped by the runner rather than by each node because the nodes
  are shared singletons.
- The reads are defensive: the v3 stream layer (`langgraph/stream/_convert.py`,
  `_mux.py`) builds only `type`/`method`/`params`/`seq`, so `run_id`/`metadata`
  are absent from some envelopes and `node_id` falls back to the display label.
- `retry_count` excludes HTTP/LLM transport retries, is `0` on a plan-less
  state (e.g. Klea RAG), and escalation compares it against `max_retries`.
- Nothing was git-staged or committed.
