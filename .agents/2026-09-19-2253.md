  `ValidationError` before LangChain's `include_raw` can capture it, so the
  node aborted.
- **Structured-output fallback.** `BaseLLMNode._invoke_llm` now runs one
  `_invoke_with_retries` loop over a callable that tries structured output
  first and latches to a plain invoke on any structured-only failure
  (`is_structured_output_failure`: pydantic `ValidationError`,
  `OutputParserException`, `json.JSONDecodeError`, or
  `STRUCTURED_OUTPUT_REJECTED`).  The plain output is parsed tolerantly,
  ending at the node's typed default.  Blank structured responses keep their
  existing empty-retry budget; infra errors still raise.
- **Capability cache.** Process-local negative cache keyed by normalised
  `(provider, model, base_url)` so an endpoint that refuses
  `response_format` is not re-probed on every node call.  Only a strict
  `is_structured_capability_rejection` (names `response_format` /
  `json_schema` / `structured output`) populates it; the generic
  `400 invalid_request_error` pattern is deliberately excluded.  Per-response
  parse failures are never cached.  `_invoke_llm` short-circuits to plain when
  the key is known-unsupported.
- **Per-node default audit.** `SummariseMemoryNode._update_state` now
  preserves state (returns `{}`) on a blank summary instead of wiping

  explicit `NO_CONCLUSION_FALLBACK` conclusion instead of an all-default

## Errors and Lessons

- **`include_raw` is not a catch-all.** It captures LangChain parser errors,
  but an SDK that validates JSON inside its own client (OpenAI) raises a
  pydantic `ValidationError` before LangChain sees the raw response.  Treat
  both error types as structured failures.
- **Classify parse errors by type, not message.** Message regex is brittle;
  reserve it for parameter rejection (no distinct exception type), and use a
  stricter predicate before trusting an error as a *capability* signal.
- **Do not cache per-response failures.** Caching a malformed-JSON response
  as "unstructured" would silently disable structured output for a model
  that does support it; only a stable capability rejection is cacheable.
- **Blank summary is data loss.** Advancing `summarised_till` on a blank
  summary discards the old conversation permanently; preserve and retry.
- **Hidden fields cause evaluation loops.** The reasoning contract keeps the
  justification in `rationale`, but `observations_text` rendered only the
  conclusion, so the Evaluator demanded "missing justification" until the model
  duplicated it into the conclusion.  Surface every field the evaluator judges
  on.
- **LLMs do not infer "optional" from an absent `required`.** Parameter lines
  must state `optional` and show non-null defaults; the picker set a restrictive
  `list_files(pattern=...)` omitting `*.toml` despite the default `"*"`.
