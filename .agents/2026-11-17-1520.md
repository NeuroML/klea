## Objective
Make a failed eval run from an earlier invocation visible in `klea-eval report`
by listing the published run directories that carry no results-index line, while
keeping the index itself completed-only.

## Completed
- Extended the report writer in `eval_pkg/klea_eval/reporting.py` to enumerate
  every published run directory under `runs/` through `workspace.list_run_dirs`,
  keep the ids present in the index in an `indexed` set, and render each absent
  directory through `_unindexed_line` with `index=missing` while incrementing a
  new `unindexed` summary counter.
- Added `workspace.list_run_dirs`, which lists the published run directories and
  skips the staging and sentinel names (`.tmp`, `.superseded`, `.overwrite`) and
  hidden names.
- Classified each unindexed directory: a complete-but-unindexed run is `drift`, a
  complete-and-archived run is `archived`, and any other residue (a directory
  without the `COMPLETE` marker) is labelled from its readable `run.json`, or as
  `case=?`, `status=incomplete` and `label=unknown` when that cannot be read.
- Covered the new behaviour in `eval_pkg/tests/test_api.py`.
- Documentation and tracker updates: `devdocs/backlog.md`,
  `devdocs/system/eval-harness-run-guide.md`,
  `devdocs/system/eval-harness-implementation.md` and `CHANGELOG.md`.

## Decision
- Failure history is a reader-side concern only: the report (and the run
  listings) surface failures by reading published directories, so the index
  stays a projection of the `COMPLETE`-marked run directories.
- The index stays completed-only, so no failed run gains an index line and the
  `klea-eval check` consistency pass stays well-defined.
- The taxonomy is: a complete-but-unindexed directory is `drift`, an
  unmarked residue is the failed case (`status=incomplete`, `label=unknown`
  when its `run.json` is unreadable).
