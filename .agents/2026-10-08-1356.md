# Session: 2026-10-08-1356

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Investigate a report (`mock-timeout-finding.md`) that `run_command` leaks child
processes on timeout, then harden the process-group termination.

## Completed

- Root-caused the leak in `run_command`'s own timeout path (it does not use the
  Linux `timeout` utility):
  - SIGKILL escalation was gated on the *direct child* (`process.wait()`), so a
    grandchild that ignores/defers SIGTERM outlived the shell and was never
    killed.
  - External cancellation (`asyncio.CancelledError`, e.g. client-side call
    timeout) bypassed termination entirely.
  - `os.getpgid(process.pid)` was used after possible reaping.
- Fixed `_terminate_process_group`: capture the pgid before signalling; SIGTERM
  the group; poll the group (`os.killpg(pgid, 0)`) for `KILL_GRACE_SECONDS`;
  SIGKILL survivors; reap the direct child. Added `_process_group_exists` /
  `_drain_process_group` helpers.
- Handled `asyncio.CancelledError` in `run_command` with a shielded group kill
  before re-raising.
- Added regression tests: SIGTERM-ignoring grandchild is killed on timeout; a
  cancelled call kills its process group. Both failed before the fix.
- Documented the detached-descendant limit in the impl/module docstring and the
  LLM-facing tool description (suggesting `ps`/`pgrep` verification).
- Updated ADR-0038 (execution wording, confirmation list, 2026-10-08 update) and
  added the whole-tree-kill limitation to `devdocs/backlog.md`.

## Errors and Lessons

- Initially conflated the finding's Linux `timeout` utility with `run_command`'s
  own asyncio timeout; the two are unrelated. Confirm which mechanism fired
  before diagnosing.
- No portable, dependency-free whole-process-tree kill exists: process groups
  (POSIX) cannot reach `setsid`/`setpgid` escapees; the only cross-platform
  option is a racy `psutil` recursive walk; native options (Linux cgroup v2 /
  `PR_SET_CHILD_SUBREAPER`, Windows Job Objects) are per-OS. Deferred.

## Open Questions

- Whether to add a best-effort cross-platform tree kill (`psutil`) or a
  platform-native isolation (cgroup/Job Objects) for daemonising commands.
