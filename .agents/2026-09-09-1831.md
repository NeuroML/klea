## Decisions (general-path architecture, not yet implemented)

- Escalation ladder, not a gauntlet: trivial input must not pay the
  planning ceremony.  Proposed graph: Init -> ModeDecision -> Guard ->
  Router (structured ``RouteSchema``: ``answer`` | ``single_task`` |
  ``plan``; the router answers chat directly in the same structured
  call -- no separate answer node) -> Act/Dispatch loop (existing
  picker/caller machinery, ADR-0020/0034) -> QuickEval (``done`` |
  ``escalate``) -> GoalSetter -> Planner -> per-step Act -> Evaluator
  -> Answer.  Trivial-chat floor: 2 LLM calls (Guard + Router).
- Classifier runs at phase boundaries, not per tool round (cost);
  act nodes do their own round evaluation; QuickEval only arbitrates
  escalation; deterministic budget backstop.
- ExplorePlanner demoted from the general path (exploration happens
  inside act loops); ToolsPicker/ToolsCaller stay shared (RAG +
  scientific path reuse them).

## Errors and Lessons

- Verify mechanisms in installed sources before asserting behaviour
  (bind_tools semantics were initially described from API knowledge;
  reading ``langchain_core``/``langchain_openai`` sources changed the
  conclusion set).
- "Native tool calling" is not one thing: endpoint `tools` field
  support (server), emission parsing (server vs app), and model
  training (emit a parseable format) are independent layers; only the
  last is common to all designs.
