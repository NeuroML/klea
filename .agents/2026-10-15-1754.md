## Objective
Two UI improvements: (1) show a concise plan-review progress summary instead
of the raw tool-call JSON; (2) make the inspection/status panes and the chat
tool blocks survive a reload by persisting a UI projection and replaying it
(recorded as the ADR-0032 update).

## Completed
Concise review progress:
- `StepOutput.summary()` + `KleaAgentState.progress_text()` (`schemas.py`);
  the `AwaitHuman` review checkpoint now carries `progress_text()` instead of
  the prompt-facing `observations_text()` (which is unchanged).  A reasoning
  step renders a truncated first-line gist.
- Rendered monospace (so tool names/paths stay literal) in the web review form
  and the new TUI review-progress `Static`, not as Markdown (Markdown would
  mangle `*`/`_`/`[]` in names and paths).

Persistent UI hydration (ADR-0032 updated; ADR-0013 amended -- no new ADR, as
ADR-0032 already owns the "stream-only -> hydrate" decision):
- Chat tool blocks are persisted as `messages` rows (`role="tool"` plus
  metadata); `server_message_to_data` rebuilds them; `get_messages` orders by
  `created_at, id` so a persisted batch keeps its order.
- New `sessions_db.chat_events` store (`add_chat_events`/`get_chat_events`),
  **purged on `delete_chat` and `delete_user_chats`** alongside `messages`.
- `chat_core.stream_response` tees the pane events (`inspect`/`state`) plus a
  per-turn `query` marker, flushed in `finally` (survives error/cancel/
  disconnect).  `usage` is deliberately **not** stored -- it is checkpointed
  state and is projected instead.
- `GET /chat/{user_id}/{chat_id}/events` (new `api/events.py`, mounted in both
  apps) + `fetch_chat_events`; the context endpoint now also returns `usage`
  (from checkpointed `usage_metrics`), which the frontends map to `token_usage`.
- Shared `replay_chat_events(chat, events)` (marker + reducer) wired into web
  (`hydrate_chats`) and TUI (`_hydrate_chat`) hydration.
- Docs: `streams.md` ("Persistence and hydration"), `api-sse-sequence.md`
  (events endpoint + boot sequence + usage), `CHANGELOG.md`, backlog.

## Errors and Lessons
- A checkpoint cannot reproduce the inspect pane's node-authored `details`
  (`input_prompt`/`unprocessed_output`/`tools_description`), so an event store
  is genuinely required -- it is not a redundant projection.  But `usage` and
  `context` ARE checkpointed, so those are projected instead of stored.
- `ty` noise persists (unresolved `textual`; `klea_utils.ui.client has no
  member ...`; TypedDict-union subscripts) -- in tests, `cast` the
  `InspectorEntry | InspectorMarker` list before indexing.

## Open Questions
- `chat_events` retention/pruning (the store grows per run).
- Client-command `system` bubbles are not persisted (the server never sees
  them); a pending `/inspect` command was noted in the backlog.
- The durable SSE item (`id:`/`Last-Event-ID`) could reuse the same event store.
