## Objective
Add a `klea list-sessions` subcommand that lists the user's chat sessions
(newest first) from the backend, as a fourth client alongside `klea tui`,
`klea web` and `klea headless`, and document it.

## Completed

- Registered `list-sessions` on the agent Typer app (`agent_app`) in
  `agent_pkg/klea_agent/ui/cli.py`, so it runs as `klea list-sessions` and the
  existing `.. typer:: klea_agent.ui.cli:agent_app` directive in
  `docs/cli/klea.rst` picks it up automatically. Agent side was chosen because
  every value it needs (`DEFAULT_SERVER_URL`, `SERVER_APP_MODULE`,
  `IDENTITY_APP_NAME`, `CONFIG_ENV_VAR`, `CONFIG_DIR`,
  `write_config_template`, `_validate_server_url`) already lives there, and
  `make_client_app` in `klea_utils` would have needed a widened signature and
  would have added the command to `klea-rag` unrequested.
- The command is a client exactly like `headless`: it resolves identity through
  the shared `resolve_user_id` seam (`--user-id` > `KLEA_USER_ID` > persisted
  local UUID for loopback), wraps the call in `_maybe_spawn_server` (spawning a
  local server when none is listening and stopping it on exit), and reads the
  sessions from the shared `klea_utils.ui.client.fetch_chats` (`GET
  /chat/{user_id}`), so it shows the same sessions as the other clients.
- Flags: `--server/-s`, `--user-id`, `--limit/-n` (default 20, `0` = all),
  `--json`, `--no-preview`, `--profile/-p` (forwarded only to a server this
  command spawns) and `--debug`. A negative `--limit` is rejected as a CLI
  error.
- Output is the fixed column order chat id, `updated_at`, title, then the
  preview: one two-line block per session, the server's REAL epoch rendered as
  a local `%Y-%m-%d %H:%M` label for display only. The preview is the record's
  `preview` verbatim -- the server already truncates it to
  `CHAT_PREVIEW_MAX_CHARS = 200` -- so the command never re-truncates or
  re-wraps it, fetches nothing else and adds no endpoint or SQL. A chat with no
  user message has no preview line, as does `--no-preview`.
- `--json` prints one JSON array (indent 2) of objects with exactly
  `chat_id`, `title`, `updated_at` (raw epoch float) and `preview` (`null` when
  absent, key omitted under `--no-preview`); the server's `user_id`,
  `overrides` and `created_at` are dropped.
- Empty result (no sessions, or a failed GET, which `fetch_chats` logs and
  turns into `[]`): the human-readable form prints
  `No chat sessions found for user <user_id>.` and exits 0; `--json` prints
  `[]` and exits 0.
- Tests: new `agent_pkg/tests/test_list_sessions_cli.py`, `CliRunner` on
  `agent_app` with an async fake for `klea_utils.ui.client.fetch_chats` and
  `klea_utils.ui.cli._maybe_spawn_server` patched to `contextlib.nullcontext()`;
  cases cover a populated listing (chat id, preview, server order, `--limit`),
  the empty message and the `--json` key set.
- Docs: a hand-written "Listing sessions" section in `docs/cli/klea.rst` after
  "Headless runs", plus matching notes in `devdocs/system/tui.md` (the session
  model, as the `--resume`/`--continue` target) and
  `devdocs/system/session-commands.md` (the client-command notes); the CLI
  reference picks the command up automatically through the existing
  `.. typer:: klea_agent.ui.cli:agent_app` directive.
- `CHANGELOG.md`: one `### Added` bullet under `## Unreleased` describing the
  new `klea list-sessions` subcommand.

## Errors and Lessons

- Server-side ordering and preview truncation were already correct, so the
  command needed no query, SQL or endpoint change: `SessionStore.list_chats`
  already sorts by `updated_at DESC` and truncates the preview. Reusing the
  field verbatim keeps a single source of truth for what a session list shows.
- Reusing the `headless` skeleton (same `--server` option object and the same
  lazy-import discipline) keeps `list-sessions --help` light and keeps the
  command consistent with the other clients.

## Open Questions

- No pagination beyond `--limit`: a very long session list is fetched whole and
  then sliced client-side. Left as-is because the endpoint has no paging and the
  listing is small in practice.

## Notes

- The command is read-only: it never creates, renames or deletes a chat.
- `--profile` follows the documented behaviour of the other clients: it only
  configures a server this command spawns itself; an already-running or remote
  server keeps its own configuration.
