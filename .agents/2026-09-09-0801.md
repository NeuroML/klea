## Objective

Fix the Anthropic cache_control bug in `BaseLLMNode._add_cache_control` (it
was set via `additional_kwargs`, which langchain-anthropic drops) and add
unit + live integration tests for prompt caching.

## Completed

- Confirmed empirically (langchain-anthropic 1.7.1 `_format_messages`) that a
  plain-string SystemMessage is sent as the bare `system` field;
  `additional_kwargs["cache_control"]` is a silent no-op.
- Fixed `_add_cache_control` (`utils_pkg/klea_utils/nodes/base.py`) to wrap the
  string system prompt in a structured text block carrying
  `cache_control: {"type": "ephemeral"}` (list-content fallback tags the last
  text block). System prompts stay plain strings at prompt-build time per user
  decision (provider is only known at invoke time).
- Added offline unit tests in `test_node_base_schema.py` (anthropic tags the
  content block, non-anthropic unchanged).
- Added `localonly` integration test `test_anthropic_cache_control_real_call`:
  real invoke via `create_configurable_model` using `claude-haiku-4-5-20251001`,
  ~390k-char system prefix (haiku 4.5 needs >=4096 cache tokens), two calls,
  asserts cache read on the second. Skips unless `ANTHROPIC_API_KEY` set.
  Passed live (run with `ANTHROPIC_API_KEY=$(pass API-keys/platform.claude.com)`).

## Errors and Lessons

- Anthropic's cache minimum is model-specific (haiku 4.5 = 4096 tokens); a
  char-based token estimate passed while the real prefix (~3.2k tokens) was
  under the minimum, so no cache was created. Size by pessimistic chars/token
  floor, not `estimate_input_tokens`.
- langchain-anthropic zeroes the generic `cache_creation` field when
  `ephemeral_5m_input_tokens > 0` (avoids double counting); read the
  `input_token_details` sub-dict and prefer `ephemeral_5m_input_tokens` for
  cache creation.
- `ChatPromptValue` requires real `BaseMessage` objects, not role/content
  dicts.
