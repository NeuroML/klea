# Session: 2026-10-06-2329

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Implement human-in-the-loop (HITL) interrupt/resume end to end (ADR-0046): a
run can pause for an explicit human decision and resume the **same** run with
its state intact, across the backend graph, API, stream clients, web UI and
TUI.  Settled the full design first, then landed it in small review-gated,
per-step commits.

## Completed

- **Design + ADR-0046** (accepted).  Verified LangGraph interrupt semantics
  empirically against 1.2.12 (pause leaves `next == (node,)`; `Command(resume=)`
  continues the same run; a plain input abandons the pending task) and recorded
  the evidence in `devdocs/system/graph-resume.md`.
- **Semantics**: interrupt == pause; answer == same execution; cancel ==
  terminal, recorded as `user_cancelled` (distinct from an evaluator
  `aborted`); failure `resume` stays separate from HITL.
- **Step-level `needs_input`** (supersedes the earlier plan-level question):
  `StepSchema.needs_input` marks a blocked (draft) step; the plan status
  `needs_input` is derived from the steps; blocked steps are exempt from the
  executable-step checks; questions are positional per step
  (`human_input: dict[int, list[str]]`), no per-question keys/dynamic schema.
- **Deterministic review approval**: `AwaitHuman` (review) captures an explicit
  `ReviewResponse` (approve/revise/cancel); approve sets `in_progress` and
  dispatches straight into execution (no Planner call); revise returns feedback
  to the Planner; cancel is terminal.
- **Generic template**: `klea_utils/nodes/await_human.py` (`AwaitHumanNode`)
  owns the mechanism; the agent `AwaitHuman` policy is instantiated twice
  (review, input).
- **Wrappers**: `run_graph_invoke` / `run_graph_astream_events` accept a
  `Command`; the stream detects a pause via `stream.interrupted()` /
  `stream.interrupts()` and emits an `interrupt` event (forwarding
  `hitl_response_schema`), suppressing the spurious `complete`.
- **chat_core** (split into `chat_core` / `chat_common` / `overrides` /
  `hitl`): a paused thread rejects a plain query/failure-resume with `409`;
  answers map to `Command(resume=...)`; question persisted as an assistant row
  on pause, answer as a user row on resume.
- **API**: `interrupt_response` / `interrupt_id` / `interrupt_cancel` on the
  agent `ChatPayload` (exactly one action), forwarded to `chat_core`.
- **SSE client**: carries the interrupt actions in the request body and yields
  the `interrupt` frame unchanged.
- **Web UI**: live flow renders the ask in the chat pane's per-turn *turn
  status* region (renamed from the ambiguous "status region" to distinguish it
  from the right-drawer *status pane*), gates the input, and submits the
  answer/cancel; reload re-presents the ask via `context` hydration
  (`pending_interrupt`).  The review form carries and shows the rendered plan.
- **TUI**: detects the `interrupt` frame, prompts (approve/revise/cancel or
  per-question answers), and streams the answer in the same turn.
- **Docs**: ADR-0046 verdict + cascade (ADR-0035/0041/0043, control-flow,
  prompt-conventions, c4-container, c4-component-agent); the agent C4 diagram
  and the tracked `example-configs/klea-agent-lang-graph.{mmd,png}` were
  synced to the regenerated topology (adds Awaiting input + Cancelled).
- **E2E polish + public docs**: the review form was given the rendered plan
  and a clear heading, and review decisions render as "Plan approved" /
  "Revision requested" (wire values unchanged, via a unified
  `render_interrupt_response`); the public docs (index, components, API
  reference), `CHANGELOG.md` and the backlog were updated for HITL.

## Errors and Lessons

- **Dynamic response schemas were the wrong default.**  An early design built
  a per-question `create_model` response schema with keys.  Rejected in favour
  of free-text positional answers tied to steps; simpler and avoids invented
  identifiers.
- **Output schemas are structure-only.**  A docstring on a model used by an
  LLM output schema leaks a JSON-schema `description` and trips the
  structure-only test; use comments, not docstrings, on those models.
- **Naming**: LangGraph's own `interrupt(..., response_schema=)` /
  `Interrupt.response_schema` must stay; our app-level stream key is
  `hitl_response_schema` to avoid confusion with an LLM/API "response".
- **Do not change HITL wire values.**  During E2E the review decision literals
  were briefly changed to display strings; that breaks the `ReviewResponse`
  `Literal` validation and the `_apply_review` dispatch.  Wire values stay
  `approve` / `revise`; only the transcript display maps them (`Plan approved`
  / `Revision requested`), now via one shared `render_interrupt_response`.
- **Generated C4 diagrams drift.**  The agent C4 Mermaid core must be
  resynced from the graph `draw_mermaid()` output whenever the topology
  changes; the reviewed doc now matches the committed `.mmd`.
