## Objective
Decide how the planner selects which prior step outputs are rendered into its
evidence prompt, replacing the ad-hoc flat `observations` dump, and land that
rule as a system note plus code routed through the state model.

## Completed
- Withdrew the proposed `references: list[int]` schema field. `depends_on`
  (`Planner_system.md:97-101`, `schemas.py:47`, `validate_plan` `:321-333`) is
  the consumption edge; a consuming step can never run in parallel with its
  producer, `depends_on` without consumption is only ordering (review gates,
  `schemas.py:36-42`), and any omitted edge would be omitted in the new field
  too, so it adds no signal.
- Ordered selector for full `entry.render()`: (1) failed steps, (2)
  transitive `depends_on` closure of every pending step, (3) Evaluator-flagged
  steps, (4) the last completed step, (5) the latest abandoned revision.
  Everything else degrades to `summary()` plus a project-root spill pointer.
  Review steps produce no `StepOutput` and need no special case.
- Single residual risk: an unrecorded consumption edge; recovery is a
  delegated read step from the spill pointer, one extra round trip rather
  than data loss.
- System note `devdocs/system/agent-planner-evidence-rendering.md`
  (`05c1af28`); selector `agent_pkg/klea_agent/evidence.py` with
  `render_plan_evidence` / `EvidenceRender` / `NO_EVIDENCE` and seven branch
  tests (`0c078b4e`).
- Routing through the state model after review: `KleaAgentState.planner_evidence()`
  delegates to `render_plan_evidence` (deferred import; derives flagged set and
  latest `plan_history` revision), and `planner.py` supplies `observations`
  from it. `observations_text()` kept unchanged because the Evaluator,
  ReasoningNode, AnswerFromResults and the tools picker depend on its exact
  bytes (`febfe200`, plus `agent_pkg/tests/test_planner_evidence.py`).
- Docs synced: note Decision/References plus section 5.9 of
  `devdocs/system/agent-node-contracts.md` describe the delegate and the
  review-step exclusion (`70d23938`).
- Verification: ruff clean, no new `ty` diagnostics (only the pre-existing
  `schemas.py` status-override error), 168 tests passing; every diff shown
  before its commit.
