# 2026-11-27 12:00 - klea headless becomes a backend client

**Authoring agent:** opencode
**Model:** opencode-go:deepseek-v4.1-flash

## Decisions

- `klea headless` no longer builds the agent graph in-process (`KleaAgent(checkpoint="sqlite")` plus `run_graph_astream_events`). It is now the third client of the backend, like `klea tui` and `klea web`: one query goes to `POST /query/stream` through `klea_utils.api.sse.stream_events`, so it shares sessions, configuration and safety settings with the interactive clients.
- Server attach/spawn: `--server`/`-s` (default `http://127.0.0.1:8006`) is handled by `klea_utils.ui.cli._maybe_spawn_server`. A loopback URL with nothing listening spawns a server for the run and stops it on exit; an already-running server and any non-loopback URL are used as-is and left running. `--profile` therefore only applies to a server this command spawns, matching the documented `tui`/`web` behaviour.
- Identity: new `--user-id`, resolved by the shared `resolve_user_id` seam (`--user-id` > `KLEA_USER_ID` > persisted local UUID for loopback), so a headless run lands in the same session list as the interactive clients. Without it, every run collapsed into the empty user key.
- Thread/chat id: `--thread-id` is kept but forwarded as the run's `chat_id`. The client API has no thread parameter; the server derives the checkpoint thread as `user_{user_id}:chat_{chat_id}`. Documented consequence: a checkpoint written by the old command under the bare `default_thread` is not continued, because its effective thread id changed shape.
- Output contract: the answer goes to stdout alone (pipe-safe); an interrupt payload is JSON on stderr; an `error` event prints its `message` plus a resumable hint on stderr; `--debug` echoes the remaining diagnostic event types to stderr. Exit codes: 0 = `complete`; 1 = interrupt, error event, or transport/spawn failure; 2 stays Typer's usage error.
- Safety toggles, verdict per flag. All are spawn-scoped, because `ChatPayload` has no path-check or HITL fields and `stream_events`' `extra` is merged into a POST body that the typed payload ignores:
  - `--path-check strict|declared|off`: keep. `off` is the guarantee that no tool call can ever pause for a path approval; `strict` (the default) is the most likely thing to stop an unattended run.
  - `--path-check-stance deny|allow`: keep, documented as meaningful only together with `--no-hitl`, since it is read only in the HITL-disabled branch of the permission resolver (deny fails the call, allow proceeds without a prompt).
  - `--hitl/--no-hitl`: keep the pair. `--hitl` (the server default) stops the run at the first ask, prints the payload and exits 1 with the checkpoint left resumable for another client; `--no-hitl` is the setting that lets an unattended run complete. Headless never answers an ask and has no stdin.
  - The toggles reach a server only through the environment of a server this command spawns (`KLEA_AGENT_PATH_CHECK`, `KLEA_AGENT_PATH_CHECK_STANCE`, `KLEA_AGENT_HITL`), exported before the spawn attempt. An already-running or remote server keeps its own settings, and a server-side ceiling always wins over session state.
  - Follow-up (not this change): making these true per-run options needs optional fields on `ChatPayload` plumbed through `stream_response`, or sending the `/pathcheck`, `/pathcheck-stance` and `/hitl` session commands first.
- Docs: `docs/cli/klea.rst` gains a "Headless runs" section; `devdocs/system/session-commands.md` rewrites the "Headless equivalents" paragraph; `devdocs/system/tui.md` names headless as a third client. `CHANGELOG.md` gains a "Changed" bullet.
