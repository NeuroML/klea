# Session: 2026-09-28-2158

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Fix the UI regression where the first query fails when no models are configured:
add per-session default models, provider-scoped credentials, and a
first-run/readiness flow, while preserving per-chat model isolation.  Also
make the inspector pane update live as nodes run (per-query collapsible
sections).

## Completed

### Model resolution (three layers)
- graph/env defaults < per-session defaults (per browser `user_id`) < per-chat
  overrides; role-level (a chat role dict wins entirely).
- Per-session default endpoints under `/chat/{user_id}/models/...`; a chat
  write promotes the changed role into the session default ("last used"), with
  a `promote_default` opt-out. `Reset` clears only the chat override.
- Legacy inline per-chat `api_key`s (shipped in `klea_utils` 0.5.x) are
  migrated into credentials at startup and stripped from overrides.

### Provider-scoped credentials
- `user_credentials` table (per user, provider + endpoint) and
  `/credentials/{user_id}` API; keys are never returned raw (masked suffix plus
  a `user`/`env`/`none` source).
- `credential_scope` / `provider_api_key_env` / `provider_requires_api_key`
  helpers; `chat_core` injects credentials into the per-run `model_overrides`
  (locked roles skipped).
- Unused-key TTL (default 7 days, `KLEA_CREDENTIAL_TTL_DAYS`; `0` disables),
  swept at startup and opportunistically on access; plaintext at rest (opencode
  parity).

### Frontend (shared NiceGUI)
- Model dialog edits session defaults (no chat) or the chat's overrides;
  model-only roles, unchanged roles are not written; "Manage API keys" opens a
  masked, write-only credential editor.
- Status pane shows the default vs chat model summary, credential tags and
  hints; a first-run "Choose models" CTA plus a one-time prompt; send is
  disabled (and guarded) until required models and keys are set.
- `ChatData` TypedDict documents the in-memory chat state schema.

### Inspector pane (live updates)
- Inspect entries now append incrementally as each node finishes (no wait for
  the `complete` event); the pane keeps every query's section for the browser
  session instead of clearing per query.
- Each send adds a collapsible query section (timestamp + query truncated to
  80 chars, full text in a tooltip); section and entry details both use
  disclosure triangles, with a separator rule between sections.
- `stream.py` dropped the `inspector_buffer`: `apply_stream_event` appends to
  `inspector_entries`, while `run_stream` adds a per-query marker and calls
  `ctx.begin_inspector_section` / `ctx.append_inspector` for incremental DOM
  updates.

## Errors and Lessons

- `SessionStore.set_override` silently no-ops when the chat row does not exist
  (it UPDATEs); callers must `create_chat` first (the models endpoint does).
  Caught by two new tests.
- TypedDicts are not assignable to `dict[...]`: a parameter that only
  truthiness-tests a chat had to accept `Mapping[str, Any] | None`
  (`resolve_chat_choice`), and `apply_stream_event` was retyped to `ChatData`.
- `ruff format --check` flags a pre-existing file inside the
  `deployments/huggingface` submodule; unrelated to this work.
- Resolved the long-standing `sse.py` TODO by extracting
  `_fetch_json` / `_fetch_json_sync`.
- NiceGUI cannot create elements from a `background_tasks` task (its slot
  stack is empty: "The current slot cannot be determined"). Fixes: wire button
  work as `async` `on_click` closures (NiceGUI awaits them in the client
  context), and enter a slot explicitly before creating elements. The
  first-run prompt uses `with ctx.dialog_container:`, and `stream.run_stream`
  already used `with ctx.stream_container:`. Documented as a warning on
  `PageContext` so this is not rediscovered.

## Open Questions

- Browser-side credential storage vs server-side: model calls run server-side,
  so client-side storage only removes at-rest persistence (not in-use exposure);
  deferred.
- Whether one-off per-chat models (without updating the default) are needed;
  "last used" currently precludes it.

## Notes

- "Per session" means the persistent per-browser `user_id`; different browsers
  are different sessions, and the "delete user session" flow resets it.
- Env vars remain the recommended credential path; the UI key store is a
  convenience.
- Send readiness excludes providers that need no key (e.g. Ollama).
