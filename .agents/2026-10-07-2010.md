# Session: 2026-10-07-2010

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Fix the web/TUI chat stream dropping with a "Connection error" during a
long-running tool call (e.g. `run_command` with a 600 s timeout), leaving no
Retry, so long-running tasks are supported.

## Completed

- Root cause confirmed empirically (Gate 0a, throwaway script in
  `/tmp/opencode/`): the client's SSE read timeout is `httpx.Timeout(300.0,
  connect=10.0)` (`klea_utils/api/sse.py`), while a long node emits no graph
  events, so httpx raises `ReadTimeout` after 300 s; the web UI turned that
  into "Connection error" with `resumable: False` (no Retry).  Reproduced the
  same path with a real local stall server (a `MockTransport` bypasses the
  socket and cannot trigger a read timeout).
- L1 server heartbeat (`utils_pkg/klea_utils/api/chat_core.py`): added
  `HEARTBEAT_INTERVAL_SECONDS = 15.0` and `_heartbeat(events, interval)`,
  wrapped around the (enriched) graph event stream in `stream_response`.  It
  reads the next event in an `ensure_future` task and waits with
  `asyncio.wait`, so a heartbeat never cancels the running node/tool; the
  wrapper is closed with `contextlib.aclosing` on every exit path.
- L2 client tolerance: named `STREAM_READ_TIMEOUT_SECONDS` in `sse.py` +
  documented the `ping` event; web (`components/stream.py`) and TUI
  (`tui/repl.py`) ignore `ping`; a transport error is now `resumable: True`
  (Retry offered); added `httpx.HTTPStatusError` handling in the web path (a
  409/4xx escaped `except httpx.RequestError`, since `HTTPStatusError` is a
  sibling of `RequestError`) and broadened the TUI to `httpx.HTTPError`.
- L3 tests: `TestStreamResponseHeartbeat` (pings interleaved with no
  drop/reorder; no ping when prompt) and `ping` ignore/pass-through tests.
- L4 + L7 devdocs: `devdocs/system/streams.md` gains the `ping` event +
  heartbeat section; `devdocs/system/api-sse-sequence.md` gains the heartbeat
  note and an explicit per-turn stream contract (one POST per turn, terminal
  `complete`/`error`/`interrupt`, no persistent connection; continuity is the
  server-side `thread_id` checkpoint).
- L5 backlog: durable/resumable SSE stream item (background run + id-stamped
  event buffer + `Last-Event-ID` replay), with buffer backend options:
  in-process, Valkey (not Redis), Kafka, RabbitMQ.
- L6b e2e (web UI, `klea web`): query asking the agent to run `sleep 360` with
  `timeout_seconds=400` completed successfully; the backend log showed
  `SSE heartbeat: no event for 15.0s, emitting ping` throughout, and no
  connection error/drop occurred.

## Errors and Lessons

- `httpx.MockTransport` does not enforce socket read timeouts, so an offline
  repro of `ReadTimeout` needs a real (even tiny local) server that stalls.
- Starlette 1.7 on ASGI 2.4 does not `aclose()` the body iterator on client
  disconnect (it relies on generator finalisation), so the inner graph
  generator could leak; `contextlib.aclosing` in `event_stream` fixes this.
- `httpx.HTTPStatusError` is a sibling of `httpx.RequestError`, not a
  subclass, so backend 4xx/5xx previously escaped the NiceGUI `run_stream`
  task; now handled (relevant once Retry is offered, since a mid-run retry
  gets a 409).
- Running the `utils_pkg` suite modifies the tracked
  `vector_stores/nml-elife/chroma.sqlite3`; restore it before committing.
- `ty` in this checkout needs the `check` subcommand (`ty check`).

## Open Questions

- Durable/resumable stream is deferred (see backlog): the heartbeat only
  prevents idle-timeout/proxy drops, not genuine disconnects.
- Tasks longer than the default 600 s need `KLEA_RUN_COMMAND_MAX_TIMEOUT`
  raised (and `KLEA_TOOL_CALL_TIMEOUT` kept above it).
