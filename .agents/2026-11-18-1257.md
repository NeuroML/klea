# 2026-11-18 12:57 -- Deterministic-only scoring (eval harness)

- Agent: `opencode`
- Model: `opencode-go:deepseek-v4.1-flash`

## Decision

Drop the LLM judge from the eval-harness scoring contract. Scoring is
**deterministic checks only**.

## Rationale

A judged verdict would enter through
`record_evaluation_result(..., score, pass_fail)` into
`task_success = all(pass_fail)`, and `task_success` is what `classify_case`,
the suite `exit_code`, `suite_score` and `pass_at_k` consume. A model-scored
pass/fail therefore could not be told apart from a machine-checked one, and the
reported outcome, the labels, the exit codes and the derived metrics would stop
being reproducible from the stored run (`run.json` + `metrics.jsonl`). A judge
also adds a second variance source and a service/credential/availability
dependency to every run.

No judge scaffolding existed to remove: the harness never had a judge client,
protocol or configuration key. The change only records the contract.

## Exit code 4, narrowed

`4` (`EXIT_GRADE_MISSING`) now means a rubric-declaring suite whose
**deterministic checks produced no grade** -- narrower and more actionable than
a general judge-unavailable fallback. A real case failure keeps `1` and takes
precedence. `2` still means the suite could not start; `0` means every case
passed.
