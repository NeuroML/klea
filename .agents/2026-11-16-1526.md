## Objective

Move the running-tools plan pane's one-line `Goal: ...` label onto the goal
schema itself, so the label and its bounding rule have a single owner, and
separate the goal line from the steps with a blank line.  Update tests, devdocs
and the CHANGELOG, then commit.

## Completed

- **Decision: the goal label lives on the schema.**  `GoalSchema.goal_label()`
  (`agent_pkg/klea_agent/schemas.py`) now renders `Goal: <bounded goal>`, and
  `MAX_PLAN_GOAL_CHARS` (80) plus `truncate_plan_goal()` moved there beside it.
  The whitespace-collapse (any run of spaces/newlines/tabs becomes one space)
  and the 80-visible-character cut with a trailing ASCII `...` are therefore
  defined once and used by every producer: the agent's structured plan content
  (`plan_content_blocks` calls `GoalSchema(goal=goal).goal_label()`) and the
  shared tools caller's plaintext `display`.
- **Duck-typed `klea_utils` fallback.**  The shared `ToolsCallerNode` must not
  import `klea_agent`, so it reaches the label through a small
  `_plan_goal_line(goal_state)` helper that calls the goal object's
  `goal_label` attribute when it is callable and otherwise returns `""`.  The
  dependency direction stays one-way and Klea RAG keeps its base behaviour.
- **Blank-line spacer, layout otherwise unchanged.**  The preformatted display
  is now `f"{goal}\n\n{display}"`, and the structured plan content emits the
  goal text block, a spacer text block (a single space, so renderers keep it),
  then the steps block.  Nothing else in the status pane moved.
- **Tests updated.**  `agent_pkg/tests/test_agent_tools_caller.py` asserts the
  three-block content (goal, spacer, steps); `utils_pkg/tests/test_nodes_tools_caller.py`
  gives its `_StandInGoal` a `goal_label()` so the duck-typed path is covered.
  Ruff check/format/isort were clean in both packages and both test modules
  passed (3 and 50 tests).
- **Docs and CHANGELOG.**  `devdocs/system/agent-node-contracts.md` (section
  5.11 `Running tools`) and `devdocs/system/streams.md` now name
  `GoalSchema.goal_label` as the owner of the label and the truncation rule and
  describe the duck-typed `klea_utils` lookup; the CHANGELOG entry records the
  blank line after the goal line.
- **Commit.**  `41bbb0c2` on branch `development`: `refactor(agent): move the
  plan goal label onto GoalSchema` (8 files, +85/-34); pre-commit hooks passed.

## Errors and Lessons

- The label cannot be imported by `klea_utils` without inverting the package
  dependency, so duck typing on `goal_label` is the seam: the shared caller
  renders whatever the state's goal object exposes and degrades to no goal line
  when the object offers nothing.
- A blank line between the goal and the steps needs a block that renderers will
  not drop; a text block holding a single space survives, an empty string does
  not.
