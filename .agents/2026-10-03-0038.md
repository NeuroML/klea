# Session: 2026-10-03-0038

**Authoring agent:** opencode
**Model:** deepseek-v4.1-flash

## Objective

Investigate (empirically) what happens when a LangGraph graph receives a
second `ainvoke` while one is already running, whether a run can be
interrupted, and then design and implement per-chat cancellation and
single-flight guard for the Klea agent/RAG servers and web UI.

## Completed

### Investigation (probes, no code)
- Confirmed the checkpointer is a *log, not a mutex*: two concurrent
  `ainvoke` calls on the same `thread_id` both run, and the last checkpoint
  writer wins (no error, no per-thread guard). The only LangGraph locks are
  checkpoint-store I/O and internal executor/retry plumbing.
- Confirmed a sentinel input (e.g. `[CANCEL]` routed to `END`) does **not**
  interrupt a running graph -- it is just another concurrent run whose
  checkpoint the original run then overwrites.
- Confirmed the real interrupt primitive is cancelling the `asyncio.Task`
  driving the run: `CancelledError` reaches the node at its next `await`,
  the checkpoint is left recoverable at `next=(<node>,)`, and the next query
  starts a clean turn from `START` (no reset needed).
- Confirmed under installed Starlette/uvicorn that `/query/stream`'s
  `StreamingResponse` generator runs in its own task (distinct from the
  request task) and that cancelling it propagates into the node; the
  generator `finally` and task done-callback both run.

## Errors and Lessons

- First cut of `ActiveRunRegistry.clear` refused to remove a *not-done* task
  (to protect against a superseded task evicting a newer run). That broke
  `run_query`, which clears from its own `finally` while its task is still
  running. Fix: `clear` removes unconditionally; the done-callback instead
  only clears when the stored task is still the same one. Caught by an
  existing test (`test_query_reuses_session` -> 409 on the second request).
- FastMCP per-call timeouts surface as `McpError`/`TimeoutError` (both
  `Exception`), so narrowing `dispatch.py` is safe; verified before editing.
- The runtime AST probe showed `except BaseException` around `gather` does
  *not* swallow an external task cancel (the cancelled future re-raises) --
  but it still violates the contract (it would catch `KeyboardInterrupt`,
  and a child-raised `CancelledError`), so it was narrowed anyway.
