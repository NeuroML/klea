## Errors and Lessons
- Pydantic v2 ignores unknown fields by default, so stale
  `EvaluationSchema(next_step=...)` calls silently fell back to the schema
  default (`evaluation="plan_done"`), making some tests pass for the wrong
  reason. Renaming a schema field should include a test grep for the old name.
- The TODO's literal suggestion ("return a retry message" from `_invoke_llm`)
  is unsafe: structured/fail-closed nodes (`RouteSchema` task, `Planner`
  unplannable, `EvaluationSchema`) rely on their all-default result, and
  `GuardNode._get_default_error_result()` returns a bare `str` while its
  `_update_state` reads `result.content`. Substitution is therefore scoped
  to structured nodes; non-structured nodes handle emptiness themselves.
- Empty substitution improves fail-closed behaviour: `EvaluationSchema`'s
  default `evaluation` is `plan_done`, so an empty evaluator result now
  correctly becomes `need_replan` via `_get_default_error_result()`.
- A separate `tool_caps` map was redundant: `ToolInfo` already carries both
  the capability and the `checkpaths` metadata (`meta`).  Unified the
  dispatch/caller contract on one `{name: ToolInfo}` map.
- Adding a `logger.debug` to `ToolsPicker._get_tool_descriptions` broke a RAG
  test that built the node via `object.__new__` (no `__init__`, no logger);
  the fixture now supplies a logger, as every real node has one.
- Autodoc + `autodoc_mock_imports`: a pydantic model whose fields annotate
  mocked framework types (`AnyMessage`, `CallToolResult`) cannot be built, so
  `BaseGraphSchema` is documented in prose.
- A *wrapped* bullet immediately after a `Use when:` / `Do not use for:`
  paragraph line makes docutils report "Unexpected indentation".  Either keep
  tool-docstring bullets single-line, or put a blank line between the label
  and the list (the latter keeps wrapped bullets readable).
- Wrapping a fastmcp tool for a cross-cutting guard must preserve its
  signature (`functools.wraps` sets `__wrapped__`), otherwise fastmcp derives
  an empty schema and drops `Context` injection.  `server.list_tools()`
  returns `FunctionTool` with `.parameters` (not `.inputSchema`).
- CSS cascade layers: NiceGUI declares `@layer theme, base, quasar, nicegui,
  components, utilities, overrides, quasar_importants` and puts Quasar's
  `!important` utilities in the *last* layer.  For `!important` declarations
  earlier layers win and unlayered rules (`ui.add_css`) are the weakest, so a
  colour override must be wrapped in `@layer overrides`; for normal
  declarations the reverse holds (unlayered wins over layers).
- NiceGUI auto-applies a `ui.colors` element whose `colors.js` sets
  `--q-primary`/`--q-dark`/`--q-dark-page` *inline* on `<body>`.  Inline
  normal declarations beat stylesheet declarations whatever their layer, so
  `--q-*` token overrides need `!important` (the `--klea-*` tokens do not).
- `dark:` maps to `body.body--dark` in NiceGUI's Tailwind, but `bg-grey-9` is
  a Quasar class, not a Tailwind palette entry, so `dark:bg-grey-9` generated
  no rule - confirm a utility exists before relying on it.
- Quasar uses two dark greys: `--q-dark-page` (#121212, body/page) and
  `--q-dark` (#1d1d1d, `q-dark` panels/drawers).  Their mismatch showed as a
  black page/tab strip around grey panels; unifying the page onto the panel
  grey removes the seam.
