## Objective
Make an unknown model-override role abort an eval run up front, with exit
code 2, instead of failing each case in turn.

## Completed
- Added one read-only pre-flight before the case loop in the pipeline: it reads
  the chat's active model map once and checks the union of the caller's `-m`
  defaults and every case's `run_config.model_overrides` roles, so a typo is
  rejected before the first case runs.
- Implemented `check_override_roles` in `eval_pkg/klea_eval/run_config.py`; the
  pipeline calls it through an injectable `check_models` seam (lazily imported)
  so unit tests can stub the backend read.
- A failing check raises `PipelineConfigError`, which `klea-eval run` maps to
  exit 2 and which names the unknown role and the roles the backend exposes;
  no run directory or index line is produced.
- The existing per-case `ModelOverrideError` path is kept as a backend-side
  fallback (and its error is wrapped as `PipelineConfigError` when raised from
  the pre-flight).
- Extracted `_normalized_seed` in `eval_pkg/klea_eval/pipeline.py` for reuse.
- Updated the tests in `eval_pkg/tests/test_pipeline.py`; tests that call
  `run_suite` directly inject `_accept_all_checker` for the `check_models` seam.
- Documentation and tracker updates: `devdocs/backlog.md`,
  `devdocs/system/eval-harness-run-guide.md`,
  `devdocs/system/eval-harness-implementation.md` and `CHANGELOG.md` now
  describe the pre-flight abort rather than a per-case failure.
