# Session Log  ---  2026-10-26-1002

- **Authoring agent:** opencode
- **Model:** deepseek-v4.1-flash

## Objective

- Restore `klea-serve` startup after the per-session MCP client pool (B2b) was
  wired into the API lifespan incorrectly.
- Complete per-session client context, fix issues found by the manual TUI E2E,
  and improve user-facing plan notices.

## Completed

- Fixed `make_app`'s lifespan: the pool was constructed with
  `graph.bundled_server_config` (nonexistent) and with a config dict where a
  client factory is required.  The pool is now created before `graph.setup()`
  with a lazy factory using `BaseLangGraph.new_mcp_client()`, and handed to the
  graph so the tool-caller node receives it.
- Split client construction out of `_create_mcp_client` into
  `BaseLangGraph.new_mcp_client()` so the shared and per-session clients use
  one code path.
- Fixed two latent B2b wiring bugs: `dispatch_tool_calls` awaited
  `pool.get(...)`, and `ToolsCallerNode` now reads the run's thread id from
  `_current_session_id` (the old hook did not exist).
- Passed the pool to `ToolsCallerNode` in both the agent and RAG graphs.
- Regression tests: app lifespan wiring and pooled-client dispatch.

## Errors and Lessons

- B2b added the pool, dispatch parameters and node parameter but no client
  factory; the lifespan call site was never exercised by tests.  A lifespan
  test now covers it.
- The per-client `env`/`cwd`/`interpreter` passthrough was the follow-up; it is
  implemented in this session (below), but with a different design from the
  earlier proposal: runtime per query, not persisted.

## Runtime client MCP context (B2 completion, ADR-0055)

- Added `ClientContext` (cwd, env, interpreter), loopback-only validation,
  env bounds, and a stable fingerprint.  Centralised the loopback check in
  `klea_utils.net`.
- Carried the context on the existing `KleaRunContext` as `client_context`;
  `chat_core` validates it and never writes it to graph state or the
  checkpoint.  Env values are never logged.
- `BaseLangGraph.new_mcp_client(context)` rebuilds only the bundled server
  entry; the session pool respawns a client when the context fingerprint
  changes.
- When `project_root` is unset, the client cwd is the effective tool/discovery
  root for the run; `/cwd` still wins and the fallback is not persisted.
- TUI flags: `--cwd`, repeatable `--env KEY=VALUE`, `--interpreter`,
  `--no-client-context`.  The whole environment is forwarded by default;
  non-loopback servers are skipped.
- Key decision: model selection stays server-resolved/persisted; the client
  context is environment only and follows the active TUI.  Folding web
  `mode`/`access_level` into the same request envelope is deferred.

## Post-E2E fixes (manual TUI/client check)

- The manual two-TUI E2E exposed a real bug: the client interpreter path was
  resolved through symlinks, so a venv's `bin/python` became the base
  interpreter, the bundled server ran outside the venv, and
  `klea_utils.mcp.server.bundled` could not be imported.  Fixed by preserving
  the absolute interpreter path (no symlink resolution) in both the TUI
  builder and server validation; regression tests cover the TUI, validation,
  and spawn config.
- `KLEA_AGENT_HOME` was documented but not wired: `resolve_storage_root` and
  the artifact-path helpers were unused, so the directory stayed empty and
  the backend still used `~/.local/share/klea-agent`.  `BaseLangGraph` now
  exposes `storage_root` (agent-specific `storage_root_env`), and checkpoints,
  sessions, the lockfile, and logs use it.  The default path is unchanged;
  RAG keeps its current path.  Tests cover the resolver, BaseLangGraph, the
  app lifespan, and the agent opt-in.

## Plan notices

- The Planner emits a one-time goal notice (goal plus optional success
  criteria) when it locks a new goal; replans do not repeat it.
- Evaluator notices use user-facing labels (DONE, SKIPPED, INCOMPLETE, NEEDS
  REVISION; PLAN COMPLETE, CANNOT COMPLETE) derived from the effective plan
  state.  Raw verdicts remain in model-facing history.  Label maps live beside
  the schema literals and are coverage-tested.
- Reasoning notices use "Step N:" for consistency.
- Documented the web/TUI tool-environment split and the `/cwd` scope.

## Windows CI fixes

- Backend lock now uses `msvcrt.locking` on Windows (with `fcntl.flock` on
  POSIX), `ctypes` process liveness/start-time probes instead of `os.kill`,
  and Windows-safe stale-lock reclamation.
- Made the affected tests Windows-portable: explicit UTF-8 source reads,
  platform-native path assertions, an abrupt `os._exit` WAL crash simulation,
  and a Windows skip for the POSIX executable-bit assertion.
