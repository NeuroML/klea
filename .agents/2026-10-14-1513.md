## Errors and Lessons

- **Never `await` a `@work` method** - it returns a `Worker`, not an
  awaitable (`TypeError: object Worker can't be used in 'await' expression`).
  Hit twice (`model_dialog._reload_info`, `credentials_dialog._load`); make the
  callee a plain `async def` run via `run_worker`, or fire-and-forget.
- **Widget method vs Textual base attribute**: a helper named `_id` collides
  with `Widget._id`, so `self._id(...)` typed as `str | None` and `ty`
  reported call-non-callable.  Renamed to `_dom_id`.
- **Test harness import-time binding**: patching `klea_utils.api.sse.*` /
  `klea_utils.ui.client.*` does not rebind names imported *into* component
  modules; the `fake_backend` fixture must patch the component modules' bound
  names too (`ui.model_config`, `ui.tui.components.{model_dialog,credentials_dialog}`).
- **Environment**: this venv's editable `klea_utils`/`klea_agent` point at the
  sibling `.../software/klea` (development) repo, so utils tests are fine (cwd
  shadows) but agent/rag tests resolve the other repo; verified them with
  `PYTHONPATH=.../klea-tui/utils_pkg`.  Installing `requirements-docs.txt`
  reinstalled `klea_utils` from this repo, incidentally resolving it.
- The editor LSP shows stale `textual` unresolved-import errors; trust the
  `ty check` CLI (24 pre-existing diagnostics, none in changed files).
- Adding `/model` legitimately changed the `/m` autocomplete to
  `["mode", "model"]`; updated the two existing assertions accordingly.
