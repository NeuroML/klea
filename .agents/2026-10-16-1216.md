## Objective
Six TUI tweaks requested after using the Textual client: quiet the console
logging that overwrote the screen, drop the status-panel `context` pane (not in
the web UI), fix the status pane's oversized top / non-scrolling bottom, make
the query input multi-line and autogrowing, and keep the styling theme-driven.

## Completed
Five atomic commits on `development`:
- `7efa1dd3` quiet console logging: `plogging.setup_root_logger` gains
  `console: bool` (stream handlers omitted) and quiets `httpx`/`httpcore` to
  WARNING (`NOISY_LOGGERS`; `--debug` restores DEBUG).  `run_tui` configures
  file-only logging; `spawn_server`/`_maybe_spawn_server` gain `quiet` (DEVNULL
  stdout/stderr) which `_run_tui` passes, so the auto-spawned server's logs no

  `height: auto` (they were each `1fr`, so the app slots ate half the pane and
  the body was clipped, leaving nothing to scroll).
- `ca5224a6` multi-line autogrowing input: new `QueryTextArea(TextArea)`
  (soft-wrap, `height: auto`/`max-height: 8`, Enter submits), with Ctrl+J (and
  Shift+Enter where supported) inserting a newline.
- `99fd128f` theme-aware error style: the errored tool header uses the active
  theme's `$error` instead of a literal `bold red`.

## Errors and Lessons
- The `spawn_server` signature change broke
  `utils_pkg/tests/test_client_cli.py::TestMaybeSpawnServer` (an exact
  `assert_called_once_with`), which targeted runs missed and only the full
  `scripts/run_tests.sh` caught.  These are now a small follow-up test fix.
  Lesson: after a shared-helper signature change, run the full package suite,
  not only the tests near the edit.
- The screen-corrupting noise was httpx's built-in **INFO** request logging from
  the server subprocess (there was no committed httpx DEBUG config), not a Klea
  logger.  `--no-access-log` does not silence uvicorn's banner or the app root
  logger, so the subprocess output had to be discarded as well.
- Shift+Enter is not portable: it needs the extended (Kitty) keyboard protocol.
  Textual's `Keys` enum names `ctrl+j` as "Newline" (`\x0a`, a distinct byte
  every terminal sends), so Ctrl+J is the reliable newline key (opencode uses
  it too).
