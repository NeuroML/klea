# Session log: bounded status-pane sections with a shared height budget

**Date:** 2026-11-18 15:19
**Authoring agent:** Klea coding agent
**Model:** opencode-go:deepseek-v4.1-flash

## Context

Both frontends render the same streamed `state_sections` (the plan, a busy tool
round, app-specific sections).  A single long section grew without limit and
swallowed the pane: the TUI status panel and the NiceGUI status drawer pushed
the rest of the overview off screen, and the pane's own scroll became useless
once one section occupied it.

The goal was to bound each section's body while keeping the outer pane
scroll authoritative, and to do it once for both frontends so the terminal and
the web cannot drift apart.

## Decisions

* **One shared, frontend-neutral rule instead of per-key tiers.**  A new helper
  `utils_pkg/klea_utils/ui/status_layout.py` estimates how many lines a section
  renders to and turns that count into a height budget in whole lines.  It
  imports neither `textual` nor `nicegui`, so both renderers consume the same
  numbers.  Every `state_sections` entry follows the same content-derived rule;
  no per-key table (and therefore no special-cased `Memory` exception) was
  introduced, because neither renderer had one before.  `details` is
  deliberately not counted: it renders inside its own nested disclosure, so the
  floor already covers it and the helper needs no JSON formatting import.

* **Budget = clamp(5, lines + 1, 30), quantised to 5-line bands.**  The
  estimate is padded by one line so a section that just fits does not
  immediately overflow, clamped to 5..30 lines, and rounded up to the next
  5-line band (5, 10, ... 30).  Two line counts in one band share a budget, so
  a section that grows by a line or two while streaming does not resize on
  every tick.  Both renderers wrap text, so the count is logical lines only.

* **`KleaScroll` for the TUI.**  A `VerticalScroll` subclass in
  `ui/tui/components/scroll.py` whose `set_content()` captures the offset, swaps
  the children, then either follows the tail (reader was within one line of
  `max_scroll_y`) or restores the offset -- the same rule `StatusPanel.set_state`
  already applies to its section list.  It is not focusable by default so the
  arrow keys keep reaching the outer `#status-scroll`; the owner enables focus
  only while the section is expanded and its body actually overflows.  The owner
  applies the budget via `styles.max_height`, keeping the widget reusable.  The
  Textual 8.2.8 APIs used (`can_focus` constructor argument, `Widget.anchor`,
  `Widget.release_anchor`) were verified in the installed sources first.

* **Per-section inline `max-height` on the web.**  Each section body is a
  `.status-entry-body` column carrying `max-height: {budget}rem` (1 rem per
  line; the bodies use Tailwind `text-xs`, line-height 1 rem).  This is the one
  sanctioned inline style: the value is per section so the class sheet cannot
  express it, and it is a layout value, not a colour, so it needs no
  `@layer overrides` wrapper.  The class supplies the floor (`min-height`),
  `overflow-y: auto` and `overscroll-behavior: contain`, mirroring the TUI
  recipe and the existing `.inspector-entry-body` idiom.

* **The outer pane keeps its scroll.**  The budget bounds one section only.
  `#status-scroll { height: 1fr; }` in the TUI and the drawer's `overflow-y-auto`
  on the web stay authoritative, and section-level scrolling is contained so it
  never chains into the pane.

## Changes

New files:

* `utils_pkg/klea_utils/ui/status_layout.py` -- `estimate_section_lines`,
  `section_budget_lines` and the `MIN_LINES` / `MAX_LINES` / `BAND_LINES`
  constants.
* `utils_pkg/tests/test_status_layout.py` -- unit tests at the tests root (not
  under `tests/ui/tui|web`) because the helper is frontend-neutral.
* `utils_pkg/klea_utils/ui/tui/components/scroll.py` -- `KleaScroll`.

Modified:

* `utils_pkg/klea_utils/ui/tui/components/status_panel.py` -- imports the
  helper and `KleaScroll`, wraps each section body in `_section_scroll`, applies
  the budget in `_section_widget` / `_update_section`, adds the
  `.status-section-body` CSS.
* `utils_pkg/tests/ui/tui/test_components.py` -- floor/cap/wrapping/focus-gating
  assertions, plus a mounted-children case under `app.run_test` (children only
  exist once mounted).
* `utils_pkg/klea_utils/ui/web/nicegui/components/status_pane.py` -- wraps each
  section body in the budgeted `.status-entry-body` column.
* `utils_pkg/klea_utils/ui/web/nicegui/components/theme.py` -- the
  `.status-entry-body` floor/overflow rule beside `.inspector-entry-body`.
* `utils_pkg/tests/ui/web/test_web_ui.py` -- asserts a rendered section body
  carries an inline `max-height` in `rem` and that no `Memory` section is
  rendered.
* `devdocs/system/tui.md`, `devdocs/system/web-theming.md` -- the budget rule,
  the `KleaScroll` contract and the new semantic class.
* `CHANGELOG.md` -- one line under `## Unreleased` -> `### Changed`.
