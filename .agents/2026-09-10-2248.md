## Objective

Design and implement the general (non-scientific) agent path's
failure/termination model, entry routing, tool-suitability handling and run
history.  Started from an infinite `step_incomplete` loop found in live
testing.

## Completed

- Diagnosed the act-path loop (Evaluator `step_incomplete` -> picker forever;
  no semantic-loop cap, no replan cap, no global budget) and fixed it with
  deterministic budgets plus a terminal failure answer.
- Implemented the general path in staged, review-gated commits:
  1. failure counters + `abort`/`unplannable` schema values;
  2. human plan-review stub (`AwaitReview`, `human_feedback`, `in_review`);
  3. picker contract (prefer `suggested_tools`; empty -> replan), caller
     always writes `tool_results`, `StepSchema.render` shows tools/deps;
  4. run history (`step_outputs` writer; messages carry query/plan/verdict/
     human/answer);
  5. budgets (`tool_retry_counts`, `step_attempt_counts`, `plan_revisions`,
     `tool_rounds`) + evaluator executed-tools input and outcome wording;
  6. `AnswerFromResults` failure branch.
- Replaced the single-entry Planner with a **narrow, fail-closed
  `RouteDecision`** (`chat` | `task`) plus a **task-only Planner**, after
  live CLI testing showed the Planner answered environment questions inline
  from assumption (it hallucinated a cwd).  `StepSchema.kind`/`ReasonStep`
  and the picker `assessment` were discarded (no reasoning-step node).
- Docs: ADR-0035 amendment, `agent-general-path-control-flow.md`,
  `CHANGELOG.md`; regenerated `agent_pkg/example-configs/klea-agent-lang-graph.{mmd,png}`.
- Live CLI acceptance on the HF endpoint: "tell me a joke" -> `chat` (2 calls);
  "full path of the folder we're in" -> `task` -> `unplannable` -> clear
  "couldn't complete" answer (no hallucination); "list files" -> full tool loop.

## Decisions

- **Topology**: `Guard -> RouteDecision -> {chat -> AnswerUser | task ->
  Planner}`.  `RouteDecision` is narrow, tool-free, memory-enabled, and
  **defaults to `task`** (fail-closed); it is the only place a model may answer
  directly.  The Planner plans (or `unplannable`) and never answers the user.
- **Budgets** bound every loop, enforced deterministically in the acting nodes:
  tool-error re-picks -> replan; non-advancing evaluations -> replan; Planner
  revisions -> `unplannable`; total picker+caller rounds -> `abort`.
- **Plans are tool-executable only**; the picker is the sole selector of the
  concrete call, with `suggested_tools` as a prior.  Outcome contract is the
  step's success criteria, judged by the Evaluator.
- **Feedback** is split by source: `evaluation` (LLM judge) and
  `human_feedback` (review); run progress lives in `messages`.
- Deferred: real HITL `interrupt`/resume (ADR-0037), `read_only|full` access
  level, a general `run_command` tool, `eval_pkg` harness, and an independent
  inline-answer verifier (needed for scientific mode).

## Errors and Lessons

- Prompt engineering cannot reliably make a model self-assess "can I answer
  this?" -- the fix is structural (narrow fail-closed routing + evidence-based
  decline).
- Empty picker selection left stale `tool_results`; the caller now always
  writes results.
- The HF model returned an empty structured `RouteSchema` for the env query;
  the fail-closed default (`task`) handled it.  Structured-output reliability
  for the router may warrant a prompt tweak if it recurs.
