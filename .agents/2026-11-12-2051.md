## Objective

Show a derived display name for a chat in the web UI chat list instead of a blank label when the chat was created without an explicit title (for example from the TUI).

## Completed

- Confirmed that naming is slug-first: a coolname slug is generated first and the human-readable display name is derived from it.
- Root cause: the run path calls store.create_chat(user_id, chat_id) implicitly without a title (chat_core.py:358 and chat_core.py:532), so the stored row has title='' , and the later titled POST is silently discarded by INSERT OR IGNORE.
- Fix: derive the title in SessionStore.create_chat via the existing _display_title helper, and normalise the values returned by list_chats and get_chat.
- Added a defensive fallback in the web chat-list component so an empty stored title still renders a derived display name.
- Commit d96baf4c (2 files changed).

## Errors and Lessons

- The blank label was a persistence problem, not a rendering problem.
- The TUI only looked correct because it derives its header from the slug, so the defect was invisible there.
- No data migration was required; the web UI must be restarted to pick up the change, and existing rows are covered by the derived title on read.

## Open Questions

- Whether slug-first naming should be revisited so that an explicit display title can be supplied at creation time.
