### Plan/step parallelism (ADR-0041, `ab6c8740`..`c798dc05`)
- **ADR-0041 accepted** (replacing the earlier draft): the plan is a DAG
  (`depends_on`), execution position is *derived* (frontier/batch) not stored;
  the draft's effect gate was dropped in favour of a deterministic caller-side
  resource guard; batch cap 8 steps / 16 calls.
- **Schema:** removed `current_step_index`; added `frontier()`,
  `next_batch()` (maximal same-kind frontier prefix, capped) and
  `render(current_numbers=...)`; `validate_plan` now requires strictly-earlier
  `depends_on` and checks acyclicity via `graphlib.TopologicalSorter`.
- **Planner:** authors the DAG (prompt no longer says "linear (no branching)");
  an all-`done` plan is deterministically marked `completed`; the router routes
  `completed`/blocked plans.
- **Batch tool path:** `ToolCallSchema.step`; the picker binds every batch
  step's calls in one invocation (calls tagged with `step`; invalid/absent ->
  first batch step; 16-call cap); results are attributed per `call.step`;
  ADaPT retry counts are per step.
- **Dispatch:** `dispatch_tool_calls` groups calls by resource
  (`ToolInfo.checkpaths` values, lexical `os.path.normpath`) and runs
  same-resource calls sequentially in call order, the rest concurrently.
- **Evaluator:** per-step verdict map (`EvaluationSchema.evaluations` +
  `overall`); `executed_tools` grouped by step; the router derives the next
  edge from the plan state (completed/aborted/replan/next batch).
- **Measurement:** new E2E `parallel_writes` - two independent writes ->
  one picker batch (steps `[1,2]`) -> concurrent resource groups -> both files
  created (`1 passed in 45.71s`).
- Reasoning steps remain **serial** (one `ReasoningNode` conclusion per round);
  recorded in ADR-0041 and the backlog.

## Errors and Lessons

- **E2E harness gap:** scenarios with no `check` report green even when the
  outcome is a failure answer.  Read the transcript, not just pass/fail.
- **Feedback is out of context without its plan version.**  A count is the right
  signal for the answer; never hand it the raw feedback or all versions.
- **Invert the plan inheritance:** the authored-plan contract is the base; the
  runtime plan (lifecycle + counters) is derived.  Widening a `Literal` in a
  subclass is valid pydantic and keeps the Planner's output schema narrow.
- **Do not fight LLM over-specification with prompts.**  Deterministic guards
  (the `list_files` fallback, the picker anti-repeat) beat more prompt text.
- **Full utils pytest mutates tracked `vector_stores/nml-elife/*`** (a
  `test_stores_retrieval` side effect).  Check the working tree after a run.
- **A batch must be same-kind.**  Tool steps and reasoning steps are dispatched
  by different nodes, so the batch is the maximal *same-kind* prefix of the
  frontier; a mixed frontier drains one kind at a time.
- **The concurrency gate is the resource, not the effect kind.**  Independent
  writes to different files must parallelise, so a read-only-only gate was
  wrong; `ToolInfo.checkpaths` gives the resource deterministically, and
  same-resource calls serialise in step order.
- **Batch the LLM call, not the tool execution.**  One picker/evaluator
  invocation covers the whole batch; the tool calls themselves are cheap and
  dispatch concurrently.
- **Do not store execution position.**  `current_step_index` was brittle (it
  allowed an all-`done` plan to point past the end); deriving the frontier and
  batch from per-step statuses + `depends_on` removed the class of bug.

## Open Questions

- **ADR-0041 residual:** reasoning steps remain serial (one `ReasoningNode`
  conclusion per round); batching it into a per-step conclusion map is deferred
  (recorded in ADR-0041 + backlog).
- **ADR-0041 measurement:** only the `parallel_writes` E2E smoke exists; a
  dedicated evaluation-harness case still needs the `eval_pkg` harness.
- The Planner completion gap (an all-`done` plan authored with `in_progress`)
  is fixed: the Planner marks such a plan `completed` and the router routes it.
- HITL interrupt/resume is deferred: it touches the whole stack.
