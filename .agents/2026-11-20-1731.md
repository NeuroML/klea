## Objective

Let a case grade itself by running a case-authored command, so a benchmark task
that has a runnable success condition no longer needs a bespoke Python check or
a hand-written rule.  Everything stays deterministic: no LLM judge, no rubric
interpretation.

## Completed

Design decisions landed:

- A case may declare `command` as an argv tuple, never a shell string, so no
  quoting or shell-injection surface is introduced and the same case file is
  portable across platforms.
- The command runs once per run with the published run `workspace/` pinned as
  its working directory, so it sees exactly the files the agent produced and
  nothing of the harness source tree.
- Grading is exit-status only: exit 0 passes, anything else fails.  Standard
  output and error are discarded, so any result to be graded must be written to
  a file an `expected_outputs` entry can check.
- A per-case `command_timeout` (default 300 s) bounds the run; a timeout or a
  command that cannot be started fails the check without an exit code.
- The check is recorded as the new `command_exit` kind, carrying the command and
  the exit status in `metrics.expectation_checks`, beside the derived
  `task_success`.
- `schema_version` stays `1.0`: the harness is unreleased, so no migration is
  needed.
- Public benchmarks ship their own pre-processing/adapter scripts that emit case
  JSONL plus fixtures the loader already accepts; the harness carries no
  benchmark-specific code and needs no repository or container binding.
- `metrics.py` was deliberately left unchanged; the new verdict rides the
  existing expectation-check record instead of a new metric field.

Tests cover exit 0, non-zero exit, timeout, pinned working directory, an
unstartable command, the recorded command and status, and the grade expectation
for a command-only case.  The full suite passes (452 passed, 1 skipped), and
ruff and ty are clean.

## Errors and lessons

- Two plans were aborted because the edit steps were bound without first
  reading the exact anchor text, so the old text to replace was unknown.  The
  lesson is to read the target regions and pin the verbatim anchors before
  binding any edit call.
- Treating `metrics.py` as an edit target would have duplicated information that
  the expectation-check record already carries; deciding explicitly not to
  touch it kept the change smaller and the record single-sourced.

## Open questions and notes

- A command sandbox and permission model is deferred: the working directory is
  pinned but there is no filesystem boundary, user or environment allowlist.
- `subprocess.run`'s timeout kills only the direct child, so detached
  descendants still need the process-group kill already tracked in the backlog.
- The expected adapter output shape is not yet documented.
- Re-hydrating an archived run's workspace would be needed before a command can
  be re-checked offline; the current decision is that a verdict is never
  re-derived by re-running it.
