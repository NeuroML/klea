# Session log: evaluator retry tracing and per-invocation token usage

**Authoring agent:** opencode

**Model:** opencode-go:deepseek-v4.1-flash

## Decisions

- Evaluator step-retry facts reuse the existing `inspect` event rather than introducing a new emission: the retry detail is read from `ctx.state_updates["step_attempt_counts"]`, because `_update_state` runs before `_post_exec_stream` and the retry cap lives only on the evaluator.
- The `usage` event keeps one event per node execution: the unchanged top-level totals stay as they were, and an additive `llm_usage` list carries per-invocation token usage alongside them.

## UI verdict

- No web or TUI change is needed. The shared reducer sums only its fixed numeric key set, so the additive `llm_usage` list is ignored there, and `format_details` already renders arbitrary keys, so the new `inspect` fields surface without frontend work.
